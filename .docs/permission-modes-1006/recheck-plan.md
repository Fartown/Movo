通用做法与约束同 `test-plan.md` 和 `.docs/full-review-1005/device-brief.md`。证据放 `.docs/permission-modes-1006/device/R2/<用例编号>/`。

本轮改动：
1. 悬浮审批卡点「允许 / 继续」后，等卡片真正撤下、目标应用回到前台再执行这一步；输入「当前焦点」改为跨窗口找输入焦点。
2. 提示词要求回复里不写工具错误码（如 USER_DECLINED）。

## 用例

| 编号 | 步骤 | 通过标准 |
|---|---|---|
| Q1 应用规则 · 输入 | 装包后先把设置应用强停（`am force-stop com.android.settings`）并清掉它的搜索历史不是必须。权限页选「手动审批」，类别规则全关，应用卡加「设置」。发「打开设置，搜索蓝牙」，每张卡都点「继续」 | 每张卡点「继续」后，那一步在屏幕上真的生效：点按「搜索系统设置项」后进入搜索页；输入「蓝牙」那张卡点「继续」后搜索框里出现「蓝牙」，不再紧接着弹一张文字相同的卡。最后搜到蓝牙相关结果，回复如实。截图每张卡、每次点「继续」后 2 秒内的画面 |
| Q2 第一次没弹卡的条件 | 接着 Q1（设置停在「蓝牙」搜索结果页、不强停），再发一次「打开设置，搜索蓝牙」。任务结束后在对话里点开执行卡，截图全部步骤 | 记录弹卡次数和执行卡里每一步的标题。只要求如实记录：如果步骤里只有「打开应用」「看屏幕」这类没有点击 / 输入的步骤，0 张卡是符合设计的；如果有点按 / 输入却没弹卡，算不通过 |
| Q3 拒绝后的回复 | 手动审批下先发「记住我喜欢喝无糖茶」（不弹卡，写进记忆），再发「清空你的长期记忆」，卡上点「拒绝」 | 出卡「需要你确认 · 删除」/「清空长期记忆？」；拒绝后记忆里仍有「无糖茶」（发「你记得我喜欢喝什么吗」核对）；最终回复里不出现 USER_DECLINED 或其他英文错误码 |
| Q4 普通动作回归 | 改回 YOLO，发「打开设置，搜索 WLAN」 | 0 张卡，正常完成 |
