## 1. 设计原则

| 原则 | 含义 | 落到界面上 |
|---|---|---|
| 安静 | 界面退后，任务在前 | 每屏只有一个视觉焦点；中性色占绝大多数，彩色只表达类别和状态；不用装饰性插图、渐变和色块 |
| 精确 | 每个数值都来自规范 | 两条对齐线、4pt 间距、三档控件高度、同心圆角；图标按字形对齐而不是按外框对齐 |
| 透明 | Movo 做了什么、依据什么、进行到哪一步，始终可见 | 数据来源标注（「来自通知与日程」）、步骤胶囊、后台任务胶囊 |
| 可控 | 用户随时能停、能接管、能撤销 | 主操作放在拇指区；执行中始终有且只有一个停止入口；危险操作二次确认并说明后果 |
| 有生命但不吵 | 装饰性循环只有光球；Agent 工作时才有「进行中」的动静 | 其他动效只用来解释状态变化，短、轻，可打断，并跟随系统「减少动画」设置（见 9） |

取舍顺序：可用性 > 一致性 > 美观。三者冲突时按此顺序决定，并在设计说明里写明原因。

## 2. 布局与间距

### 2.1 栅格与对齐线

- 基础单位 4，间距只能取：2、4、8、12、16、20、24、32、40、48、64。
- 例外只有两类，且不作为独立间距使用：① 由组件尺寸推导出的内边距（如 60 高行里 40 底块上下各 10、56 底部栏里 32 按钮上下各 12、卡片上下 6 使首行图标距卡片边 16）；② 字形对齐补偿（1、7、9 等，见下文图标按字形对齐）。
- 全页只有两条对齐线（右侧对称）：
  - **边距线 20**：内容分组标题（`Section/Header`）、所有卡片与输入框的外沿、顶栏图标字形。
  - **内容线 36**（20 + 卡片内边距 16）：卡片内图标底块、卡片内文字、输入框占位文字、卡内标题行（`Card/Title`）与卡片页脚（`Card/Footer`）。
- 横向滚动列表首项从边距线开始，末项右侧同样留 20；露出下一张卡的一部分（≥ 40）暗示可滑动。
- 图标按字形对齐：线条图标在 24 框内有留白，要让看得见的笔画落在对齐线上，必要时调整容器内边距（例：顶栏左内边距 7 = 20 − 10 − 3，菜单笔画从 3 起；右侧「+」笔画到 19 止，右内边距取 6）。

### 2.2 纵向节奏

| 位置 | 值 |
|---|---|
| 顶栏高度 | 56 |
| 顶栏到首个内容 | 16 |
| 区块之间 | 32（内容页：首页、对话）；列表页（设置、执行详情）：卡片之间 16，顶栏到第一张卡片 12 |
| 分组标题到内容 | 12（`Section/Header`）；列表页的分组标题在卡片内，见 `Card/Title` |
| 卡片内边距 | 16（列表卡片上 16、下 8，行内再各 10） |
| 列表行 | 最小高 60 = 上下 10 + 图标底块 40 |
| 标题与副标题 | 0（行高自带间隙） |
| 输入框距手势条 | 8 |

### 2.3 尺寸

| 用途 | 值 |
|---|---|
| 小控件（胶囊、行内按钮、步骤标签、推荐追问芯片） | 高 32 |
| 中控件（输入区按钮、思考芯片、圆形按钮） | 高 40 |
| 大控件（整行主按钮、底部操作） | 高 48 |
| 无底色图标按钮 | 热区 44，图标 24 |
| 最小触控热区 | 44（视觉小于 44 的控件向外扩热区；相邻控件的热区不重叠）；唯一例外：浮窗紧凑档 32 |
| 图标底块 | 40，圆角 12，图标 20 |
| 行内操作按钮最小宽 | 64 |
| 紧凑档（仅浮窗） | 24 按钮 / 12 图标，热区向外扩到 32（全 App 唯一允许小于 44 的热区）；只用于浮在其他 App 上的展开卡，追求信息密度；App 内不用 |

分组标题有两种，按页面类型选用，不混用：

| 组件 | 用于 | 规格 |
|---|---|---|
| `Section/Header` 内容分组 | 首页、对话等内容页 | `Title/Section` 16 主色，对齐边距线 20；右侧可放「全部 ›」；到内容 12，区块之间 32 |
| `Card/Title` 卡内标题 | 设置页、执行详情页等列表页（2026-09-25 定稿，取代卡外的 `Section/List`） | 放在卡片内最上方：`Label/Medium` 13 次要色，左右内边距 16（对齐内容线 36），上 16、下 4；右侧可放说明或值（`Label/Regular` 三级色）。与首页「为你留意」卡片的标题行同一写法。卡片外不再放分组标题 |

侧边栏的日期分组 `Drawer/Section` 不在卡片里，保持 8.6 的规格。

同一行内的按钮高度必须一致，用颜色区分主次，不用尺寸区分。不按重要性放大按钮；唯一例外是浮窗紧凑档（见上表），它是整体缩小而不是区分主次。

## 3. 圆角

同心规则：**外层圆角 = 内层圆角 + 内边距**。嵌套元素贴近外层角时必须满足，否则弧线不平行。

| Token | 值 | 用于 |
|---|---|---|
| `radius/xs` | 8 | 标签、提示气泡、小缩略图 |
| `radius/sm` | 12 | 40 图标底块、菜单项 |
| `radius/md` | 16 | 32 高胶囊与小按钮 |
| `radius/lg` | 20 | 40 圆形按钮、弹出菜单（= 12 + 8） |
| `radius/pill-lg` | 24 | 48 高胶囊（执行卡摘要条）、整行按钮 |
| `radius/xl` | 28 | 所有容器：卡片、输入框、底部面板（= 12 + 16 = 20 + 8） |
| `radius/full` | 999 | 胶囊、圆形 |

屏幕圆角 36 是设备外形（稿中手机外框、侧边栏露出的主页面、全屏容器变形的终点），不是界面 Token，不用于组件。

### 4.2 类别色（成对使用：浅底 + 深色图标）

每个颜色有固定语义，不可挪作他用：

| 色 | 底 / 图标 | 语义 | 例 |
|---|---|---|---|
| Indigo | `#EEF0FF` / `#4F56E3` | Agent 与 AI、选中 / 开启态 | 操作 App、思考开启、执行中步骤、「为你留意」 |
| Amber | `#FFF1E3` / `#D2640C` | 时间与系统 | 闹钟、日程、提醒、设备状态 |
| Green | `#E6F5ED` / `#178A55` | 完成与感知 | 读懂屏幕、完成✓、在线状态点 `#1FB768` |
| Blue | `#E5F1FC` / `#1A72C8` | 信息与网络 | 联网调研、浏览器、链接 |
| Rose | `#FDEBEC` / `#D63C4A` | 通知与风险 | 通知、错误、危险操作 |
| Graphite | `#EFEEE9` / `#3A3936` | 开发者与底层 | 终端、文件、日志 |

Token 名：`accent/<色名>-bg`（底）与 `accent/<色名>-fg`（图标 / 文字），如 `accent/indigo-bg` = `#EEF0FF`、`accent/indigo-fg` = `#4F56E3`；Figma 变量同名。

规则：

1. 主操作用 `action/primary-bg` 浅 Indigo 实底 + `action/primary-fg` 图标 / 文字，不用纯黑、不用品牌渐变；开关的开启态用同一组颜色（见 8「开关」）；选中 / 开启的芯片用更浅的 `accent/indigo-bg`。主操作只比周围按钮「深一档」，不做成全页最重的色块（2026-09-24 定稿，候选对比见 Figma「配色候选」看板）。
2. 类别色图标对浅底 ≥ 3:1；文字只允许用 Indigo（4.9:1），其他类别色不用于文字。
3. 一屏出现的类别色不超过 4 种（不含光球）。
4. 颜色不能是唯一的状态信号：开关的开 / 关同时用滑块位置、滑块颜色与「填充 vs 描边」区分，错误同时有图标与文字。

### 4.3 品牌色

光球渐变：`#FFC2A6` 蜜桃 → `#FF9EC2` 粉 → `#B39BFF` 丁香 → `#8CC6FF` 天蓝 → `#BFEFE3` 薄荷。只用于光球、它的背景光晕，以及操作其他 App 时的屏幕边缘光晕，不用于按钮、文字、图标。

## 5. 字体

- 中文：系统字体（Noto Sans CJK / 厂商字体），不打包中文字体。
- 数字与英文：Inter（约 300KB，随包），时间与计数使用等宽数字（`tnum`）。
- 字重只用 Regular 400 与 Medium 500，界面中不用 Bold。

| 样式 | 字号 / 行高 | 字重 | 用于 |
|---|---|---|---|
| `Display/Greeting` | 30 / 40，字距 −0.5 | Medium | 首页问候、语音转写，每屏最多一处 |
| `Title/Page` | 22 / 30，字距 −0.3 | Medium | 保留备用（二级页标题已改为顶栏居中 `Body/Strong`，当前无使用处） |
| `Title/Section` | 16 / 22 | Medium | 分组标题 |
| `Body/Strong` | 15 / 22 | Medium | 列表标题、卡片指令 |
| `Body/Regular` | 15 / 22 | Regular | 说明文字 |
| `Body/Reading` | 16 / 26 | Regular | 对话消息、长文 |
| `Input/Placeholder` | 16 / 24 | Regular | 输入框 |
| `Label/Medium` | 13 / 18 | Medium | 按钮、胶囊、分组说明 |
| `Label/Regular` | 13 / 18 | Regular | 副标题、元信息 |
| `Micro/Medium` | 12 / 16，字距 +0.2 | Medium | 类别标签、按钮下方说明 |
| `Numeric/Status` | 14 / 20 | Inter Semi Bold | 仅用于稿中模拟的系统状态栏时间（系统界面，不属于 App 字重规则）；App 内不使用 |
| `Numeric/Label` | 13 / 18 | Inter Medium | 数字与英文标签 |
| `Numeric/Badge` | 10 / 12 | Inter Medium | 仅用于 14 高角标里的数字（当前无使用处，保留） |

排版规则：

- 双色标题：第一行 `text/primary`，第二行 `text/tertiary`，只用于 Display。
- 截断：标题与副标题 1 行省略；卡片指令最多 2 行，优先手动断行保证语义完整。
- 中文与英文、数字之间加半角空格（「3 条」「Kimi K2.6」）；中文用全角标点；并列分隔用不带空格的「·」（「正在执行·第 4 步」「15:02 开始·15:03 结束」）；日期与时间按中文习惯连写（「9月20日」「15:02」），不加空格；省略用「…」。
- 系统字号放大到 130% 时文字换行、容器变高，不允许裁切。

## 6. 图标

- 线条风格（Lucide 体系），24 网格，圆头圆角。
- 尺寸与线宽固定配对：24 → 1.75，22 → 1.7，20 → 1.6，16 → 1.5，14 → 1.4，12 → 1.4（12 用于浮窗紧凑档的按钮与步骤图标）。
- 用途：顶栏 24；按钮与图标底块 20；芯片、胶囊、行内 16；标签内装饰 14。
- 颜色：中性底上用 `text/primary`（弱化用 `text/secondary`）；类别底块上用对应深色；除品牌 Logo 外不用多色图标。
- 品牌 Logo：圆形裁切，外加 0.5 描边，放在 40 浅底圆按钮中时尺寸 22。
- 同一语义全 App 只用同一个图标：麦克风 = 语音输入（转文字）、声波 = 语音对话、键盘 = 打字 / 文字补充、「+」在顶栏右上 = 新建对话、在输入框左下 = 添加附件（同一图标按固定位置区分，两处不会同屏相邻）、✕ = 取消 / 关闭、✓ = 完成、↑ = 发送、■ = 停止、‖ = 暂停、▶ = 继续。不带文字的 ↑ ■ ▶ 只出现在主按钮位；其他位置（展开卡的暂停 / 结束任务 / 继续、执行卡的结束任务）必须带文字。

### 6.1 应用图标（2026-09-26 定稿 · B7「同色浅调 M」）

Figma「07 · App 图标 · 候选」→「B7 · 定稿导出」；候选演进 A–D → B1–B5 → B6–B10，选定 B7（反馈：白色 M 太突出、与底色不融合）。

| 层 | 规格 |
|---|---|
| 背景 | 自上而下线性渐变 `#F4F3EF`（bg/canvas）→ `#E6DDFF`（浅丁香） |
| 前景 | 108 画布居中光球直径 62（在 66 安全区内）：丁香底 `#EDE6FF` + 品牌角向渐变（模糊 = 直径 16%）+ 左上白色高光；下方 Indigo 18% 柔和投影（y 5%、模糊 16%），**不用光球外发光**（小尺寸发虚） |
| M | 两段弧，笔画 6.5、圆头；描边为光球同色系浅调渐变（左→右 `#FFE6DA` → `#EFE8FF` → `#DDEFFF`），90% 不透明度；**不用纯白**，只比底色亮一档 |
| 单色（Android 13+） | 直径 62 的圆盘镂空同一 M（笔画 6.5 轮廓化），单色，由系统按壁纸取色 |
| 启动页 | 同一前景，落在 bg/canvas 启动页底色上（不另设背景色） |

### 7.1 材质：浮窗半透明 `Material/Glass`

| 项 | 规格 |

### 8.2 输入与快捷操作

输入区的按钮逻辑（所有状态都遵守）：

1. **输入方式和 Agent 状态分开放**：文字行右端放「怎么输入」（麦克风 = 语音输入、声波 = 语音对话）；工具栏右下主按钮只放「Agent 的下一步」（发送 / 停止 / 继续）。语音是输入方式，不是 Agent 状态，不占主按钮。
2. **同一屏只有一个停止入口**：App 内 = 输入框主按钮 ■（任务卡、执行条只显示进度和「查看」）；App 外 = 悬浮球展开卡的「暂停」，暂停之后才出现「结束任务」。不会同时出现两个长得像「停」的按钮。
3. **状态切换时按钮原地替换**，位置不跳；执行中不可用的控件直接隐藏，不显示禁用态。

主按钮状态机（`Button/MainAction`，Figma 看板「主按钮 = Agent 状态机」）：

| Agent 状态 | 输入框 | 主按钮 | 点击 |
|---|---|---|---|
| 空闲 | 没有内容 | 发送 ↑ 置灰（`bg/surface-muted` + 三级色箭头） | 不可点 |
| 空闲 | 有内容 | 发送 ↑（主操作色） | 发送，Agent 进入运行中 |
| 运行中（思考 / 执行 / 回答 / 播报） | 没有内容 | 停止 ■（主操作色） | 停止本次运行，回到空闲；已完成的步骤和已输出的内容保留 |
| 运行中 | 有内容 | 发送 ↑（主操作色） | 作为补充交给当前任务（见 8.4），发出后回到 ■ |

| 已暂停 | 有内容 | 发送 ↑（主操作色） | 作为补充记下（见 8.4），任务仍保持暂停，发出后回到 ▶；继续后下一步按补充执行 |

原代码现状（`AgentChatInputBar.kt`，改版前）：执行中同时显示独立的停止按钮（「取消当前任务」）和发送按钮（「排队发送」），麦克风图标实际进入的是语音对话。需改为：停止与发送合并成一个主按钮，按上表切换；麦克风改为语音输入（听写进输入框），新增声波按钮进入语音对话。

语音相关有两个不同的功能，入口和图标严格区分：**语音输入**是说话转成文字、可以先编辑再发送；**语音对话**是连续多轮对话、自动发送、有声回复（App 内在聊天页原地进行；从 App 外唤起时在半屏对话浮层里进行；执行中在其他 App 里时在悬浮球展开卡里进行——三处是同一套交互）。

| | 语音输入 | 语音对话 |
|---|---|---|
| 本质 | 一种输入方式：说话代替打字 | 一种对话模式：免手持、连续多轮 |
| 文字去向 | 写进输入框，可编辑后再发 | 停顿后自动发送 |

| 持续 | 一次 | 持续聆听，可打断，直到切回文字或说「结束对话」 |

| 场景 | 语音输入（麦克风） | 打字 / 编辑（键盘） | 语音对话（声波） | 停止（■） |
|---|---|---|---|---|
| App 内输入框 | 文字行右端麦克风，32 按钮 / 20 图标（x = 324 中心） | 点输入框 | 文字行右端声波（麦克风右侧，中心与主按钮对齐 x = 364）→ 输入框原地切换为语音模式 | 输入框主按钮 ■ |
| 执行中 · 其他 App | 补充输入框里的麦克风（与输入框相同） | 展开卡里的键盘，弹出补充输入框 | 展开卡里的声波 / 长按悬浮球 / 唤醒词 → 展开卡进入语音模式 | 展开卡「暂停」→「结束任务」 |
| 从 App 外唤起（唤醒词「你好小莫」/ 电源键） | 浮层输入框的麦克风 | 「切回文字」或点输入区 | 半屏对话浮层，输入框直接处于语音模式 | 浮层输入框主按钮 ■；浮层右上「关闭」只关浮层 |

语音对话**没有独立的全屏页**：App 内在聊天页原地进行；App 外唤起时弹出半屏对话浮层（顶部把手 + 会话标题 + 展开到 App + 关闭，内容与 App 内对话完全相同），可拖到全屏或展开进 App；Movo 需要操作其他 App 时浮层收起为悬浮球，语音会话不中断，转到展开卡的语音模式，回到 Movo 后再转回输入框。

### 8.2.1 执行条 `Composer/TaskBar`

任务卡滚出屏幕时，在输入框上方 8 处出现：宽 372、高 40、圆角 20，`bg/surface` + 描边 + E1；16 小光球 +「正在执行·第 N 步」（Q3 光带）+ 计时（右对齐）+ `Button/Pill`「查看」（打开执行详情页）；左内边距 12，「查看」胶囊距右边 4（圆角 20 = 16 + 4 同心），上下 4。只显示进度，不放停止（停止在正下方的主按钮 ■）。点条身滚回任务卡；任务卡回到屏幕内时隐藏。

### 8.3 输入框语音模式 `Composer/Voice`

点文字行右端的声波后，输入框原地切换为语音模式。**骨架与文字模式完全相同**（上行内容 + 下行工具栏，总高 100 起），只换内容，按钮位置不跳：

| 部分 | 规格 |
|---|---|
| 上行（替代文字行） | 最小高 32，左内边距 8：指示（聆听 = Indigo 音量条 / 播报 = 扬声器 16 / 连接中 = 灰点）+ 间距 8 + 文字 `Input/Placeholder` 16/24。聆听：实时字幕，已确认部分主色、未确认部分三级色；无字幕时显示「正在聆听…」次要色。**发送后输入框立即回到聆听**：字幕清空，显示「正在聆听…」，可以接着说（Agent 执行中说的话作为补充，见 8.4）；Agent 的思考与执行进度只显示在对话里（执行卡、思考块），输入框不出现「思考中」，不因 Agent 在忙而不可输入。播报：「正在播报·说话即可打断」（次要色，不重复显示原话和回答，它们已在对话里）。字幕**最多 3 行**，顶部 16 淡出；指示跟随最新一行（底对齐） |
| 下行（工具栏） | 高 40，间距 8：左 40 浅底圆「切回文字」（键盘 20，占附件「+」的位置）→ 中间一行提示 `Micro/Medium` 三级色（聆听「停顿后自动发送」/ Agent 忙（思考或执行中）「停顿后补充到当前任务」/ 播报「说「别念了」也能停」/ 连接「最多等待 5 秒」）→ 右 40 主按钮 |
| 主按钮 | 与文字模式同一个状态机：Agent 空闲时 = 发送（有字幕可点，不等停顿立即发；无字幕置灰）；Agent 忙（思考 / 回答播报 / 任务执行中）= 停止 ■。执行中聆听时说的话停顿后自动作为补充发出，主按钮保持 ■ |
| 播报怎么停 | 不单设「停止播报」按钮：说话即可打断；说「别念了」；任务空闲时点 ■ 就是停止这次回答（播报属于回答的一部分） |
| 退出 | 点「切回文字」或点上行任意位置；口令「结束对话」 |
| 状态流转 | 连接中（最多等 5 秒，超时提示重试）→ 聆听 →（停顿后自动发送）→ 立即回到聆听，Agent 在对话里思考 / 执行，主按钮 = ■ → 有语音回复时播报 → 播报完回到聆听；用户说话会打断播报并直接进入聆听。输入框里没有「思考」状态 |

### 8.4 执行中补充要求

执行中再发的话（打字、语音输入、语音对话）不排队、不开新任务，而是**作为补充进入当前任务，下一步生效**。App 内和悬浮球里规则相同。

| 部分 | 规格 |
|---|---|
| 入口 | 执行中的输入框照常可用，占位文字「补充要求，下一步生效…」；有字时主按钮为发送 |
| 显示位置 | 任务卡时间线末尾新增一行 `Work/Step` Supplement：Indigo 转折箭头 16 +「你的补充」`Label/Medium` + 浅底引用块（`bg/surface-muted`，圆角 12，内边距 10 / 6）显示原话 `Body/Regular` + 右侧状态「下一步生效」→ 采纳后「已采纳」 |
| 生效时机 | 当前这一步（模型回合与工具批次）完成后被采纳，不打断正在进行的请求；暂停时发出的补充先记下，任务不会因补充而恢复，继续后第一步即采纳 |
| 多句补充 | 按发送顺序依次追加为多行，依次采纳 |
| 实现（2026-09-25） | App 内执行中发送与语音对话执行中说的话都走运行时 steering 通道（Wire `MSG_STEER`，与悬浮球「补充」同一路径）；带附件、或本轮正在收尾未被接收时，退回原来的排队（`queuedTextSubmission`），文字不会丢。「已采纳」判定：补充之后出现新的思考 / 工具步骤，或本轮结束 |

### 8.5 执行任务中的语音交互

任务通道和语音通道互不阻塞：执行中随时可以说话，说的话在任何界面都作为补充进入当前任务（见 8.4），区别只在承载的界面：

| 场景 | 语音输入（麦克风） | 语音对话（声波 / 唤醒词） | 说的话去哪里 | 停止 |
|---|---|---|---|---|
| App 内（聊天页） | 点麦克风 → 文字写进输入框 → 发送 | 点声波 → `Composer/Voice`（task=Running）：提示「停顿后补充到当前任务」 | 作为**对当前任务的补充**，下一步生效，显示在任务卡时间线「你的补充」 | 输入框主按钮 ■（语音模式下同一位置）；口令「取消任务」立即生效 |
| 其他 App（悬浮球） | 点键盘打开补充输入框，框内麦克风听写（与 App 内输入框相同） | 点展开卡的声波、长按悬浮球或说「你好小莫」→ 展开卡原地进入语音模式（与 `Composer/Voice` 同一交互），停顿后自动发送 | 作为**对当前任务的补充**，下一步按新要求执行，任务不中断 | 展开卡「暂停」→「结束任务」；口令「暂停」「取消任务」 |

两处语音对话的交互完全一致：进入方式、状态流转（聆听 → 发出 → 继续聆听 → 播报）、「切回文字」都在左下，执行中说的话在两处都是补充到当前任务——App 内和其他 App 规则相同。停止的形态按场景不同：App 内是主按钮 ■（用户在看对话，停止即结束本次运行）；App 外是先「暂停」（Agent 正在操作屏幕，第一需要是让它立刻停手，再决定继续还是结束）。

补充规则：

- **不排队，直接补充**：执行中说的每一句（打字或语音）都立即交给当前任务，作为补充在当前这一步完成后被采纳（运行时 steering 机制：不打断正在进行的请求和工具）。多句补充按顺序依次采纳。想做一件无关的新事：等任务结束，或先停止当前任务。
- **跨界面不断线**：同一次语音会话在 App 内输入框、App 外对话浮层、悬浮球展开卡之间切换时保持连接和上下文，只换承载的界面。
- **异常提示 `Composer/Notice`**：点麦克风或声波时，如缺少麦克风权限或未配置豆包语音，在输入框上方 8 处显示提示条（图标底 32 + 标题 + 说明 +「去开启 / 去设置」），同时最多一条；处理完成后自动消失并直接开始听。

## 9. 动效

### 9.0 原则

动效只用来回答三个问题，回答不了的状态变化一律直接切换：

| 目的 | 回答的问题 | 例 |
|---|---|---|
| 空间连续 | 东西从哪来、到哪去 | 用户气泡从输入框升起、执行卡收成摘要条、浮层收进悬浮球 / 从悬浮球展开 |
| 操作确认 | 我的操作被接收了吗 | 按压、开关、发送 → 停止 |
| 存活信号 | Agent 还在工作吗 | 加载圈、光球、边缘光晕、悬浮球状态弧 |

规则：

1. **进场减速、退场加速**；退场时长取进场的约 70%（见 9.1 退场列）。
2. **同类变化用同一条曲线、同一档时长**；页面代码里不出现裸写的毫秒数和曲线。
3. **循环动画**：装饰性循环全局只有光球（首页光球、悬浮球光球）；表示「进行中」的指示（加载圈、小光球、Q3 光带、状态点光晕、悬浮球状态弧、边缘光晕往复）只在进行中循环，状态结束立即停止。其他任何元素不循环。
4. **位移距离**：小元素 ≤ 8（区块进场 8、时间线新行 6、胶囊替换 4），面板、气泡与输入框 16，屏内自动动画最大 24；跟手动画（侧边栏、浮层拖动、返回手势）跟随手指，不受此限。
5. **不动的东西**：计数与计时（「第 4 步」「00:18」「3 条」）直接换数字，不滚动、不闪；正文字号、颜色 Token 切换不做过渡以外的效果；不做纯装饰的进场动画（除首页进场一次）。
6. **可打断**：所有动画都能被新的状态打断，从当前值继续过渡到新目标，不回到起点、不排队。
7. 遵守「减少动画」（9.8）。

可播放演示：Figma「定稿 · 设计稿」页「06 · 动效演示」分区（M2 执行卡完成 → 摘要条、M3 其他 App 中执行 → 完成（悬浮球保留）、M4 语音停顿 → 自动发送 → 回到聆听、M5 点击与切换 12 种控件反馈、M6 质感动效 Q2 / Q3 / Q5、M7a 首页 → 对话（Q1 文字飞成气泡 + Q6 光球延续）、M7b Q4 悬浮球 → 对话浮层、M7c Q4 设置行 → 二级页、M7d Q7 顶栏滚动态、M7e Q4 执行卡 → 执行详情页、M8 Q8 完成的一道光），关键帧的时长与曲线全部取自本节 Token，选中画框即可播放。

### 9.1 时长

| Token | 进场 / 状态变化 | 退场 | 用于 |
|---|---|---|---|
| `duration/instant` | 100ms | 100ms | 按压反馈、颜色变化 |
| `duration/fast` | 160ms | 120ms | 图标切换、芯片与开关、弹出菜单、小元素淡入 |
| `duration/standard` | 240ms | 170ms | 卡片展开收起、高度变化、区块进场、列表增删、对话框 |
| `duration/slow` | 360ms | 250ms | 页面切换、底部面板、浮层弹出与展开、侧边栏 |
| `duration/ambient` | 4000ms | — | 光球呼吸、边缘光晕亮度往复 |
| `stagger` | 40ms | — | 同屏多元素依次进场，最多 4 级（超过 4 个的从第 5 个起与第 4 个同时） |

固定节奏（不是 Token，但全 App 统一）：加载圈 800ms 一圈；悬浮球状态弧 1200ms 一圈；光球渐变 12s 一圈；小光球渐变 3s 一圈；Q3 光带扫过 1200ms + 停 400ms；状态点光晕 1600ms；点击指示保持 200ms；执行卡完成后停留 600ms 再收起；展开卡 4s 无操作自动收起；展开卡「已补充」停留 1500ms；「已复制」✓ 停留 1400ms。

### 9.2 曲线

| Token | 值 | 用于 |
|---|---|---|
| `easing/standard` | `cubic-bezier(0.2, 0, 0, 1)` | 屏内位移、尺寸与高度变化、交叉淡化 |
| `easing/enter` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 进场 |
| `easing/exit` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | 退场 |
| `easing/linear` | `linear` | 加载圈、状态弧、光球与光晕的旋转、倒计时进度环 |
| `spring/snappy` | 阻尼 1.0，刚度 1500 | 按压缩放 |
| `spring/gentle` | 阻尼 0.85，刚度 400 | 拖拽松手吸附、悬浮球出现与贴边 |

交叉淡化（A 换成 B）：A 用退场时长淡出，B 同时开始用进场时长淡入，两者重叠，不等 A 消失再出 B；需要缩放的图标切换，两者都在 0.72 ↔ 1 之间缩放。

### 9.3.1 点击与切换

**点击的四条规则**

1. **按下即反馈**：手指接触后一帧内出现按压态（`instant`），不等松手、不等点击判定；不用 Material 水波纹。
2. **松手即执行**：点击的结果（跳转、状态变化、弹出）在松手时开始，与回弹同时进行，不等回弹结束；手指滑出控件再松手 = 取消，只回弹不执行。
3. **结果慢就原地等**：结果 100ms 内不能出现（网络、权限、启动服务）时，按钮内容原地交叉淡化为 16 加载圈，按钮保持可见、不可重复点；不出现「点了没反应」。
4. **禁用控件不反馈**：不缩放、不叠加、无触感；需要说明原因时在松手后弹出提示。

**按压反馈（按控件类型）**

| 控件 | 按下（`instant` + `easing/standard`） | 松手 |
|---|---|---|
| 卡片（内容卡、能力卡、为你留意卡、执行卡） | 缩放 0.98 + 整卡 `overlay/pressed` | 回弹 `spring/snappy`，叠加层淡出 `fast` |
| 实心按钮（主按钮、圆形按钮、整行按钮、行内按钮、胶囊、芯片） | 缩放 0.95 + 叠加层（`overlay/pressed`；主操作浅 Indigo 底同样适用） | 同上 |
| 无底色图标按钮（顶栏菜单与「+」、返回、复制、重试、更多） | 图标不缩放；40 圆形 `overlay/pressed` 从 0.8 放大到 1 并淡入 | 圆形淡出 `fast` |
| 列表行（会话行、设置行、菜单项、为你留意的行） | 整行 `overlay/pressed`（被卡片或行圆角裁切），不缩放 | 淡出 `fast` |
| 文字链接（「全部 ›」「查看」） | 不透明度 → 60% | 回到 100% `fast` |
| 开关 | 滑块朝将要移动的方向拉长 22 → 26 | 见下表「开关」 |
| 输入框 | 无按压态；点击后光标出现，键盘按 9.4 |  |

缩放量按面积定：面积越大缩得越少，保证视觉位移都在 2–4 之间（卡片 0.98 ≈ 3，40 按钮 0.95 = 2）。

### 9.3.2 质感动效

在 9.3–9.3.1 的基础动效之上，只在最常看的几处加一层「质感」。每一项都有减少动画时的替代（见 9.8），都能被打断。

| # | 动效 | 规格 | 用在哪 |
|---|---|---|---|
| Q1 | **文字飞成气泡**（共享元素） | 发送瞬间，输入框里的文字不淡出，而是连同一个透明底框一起作为「气泡」出发：起点 = 输入框文字行的位置与宽度，终点 = 用户气泡的位置与尺寸；位置与尺寸 `slow` + `easing/standard`；气泡自身的 `bg/surface` 底色与 0.5 描边在前 50% 淡入；文字按气泡的最终排版绘制，第一行起点与输入框文字重合，换行不同时文字在前 30% 交叉淡化为气泡排版。输入框同时清空，不再单独淡出文字 | 每次发送（首页 → 对话第 ③ 步、后续发送） |
| Q2 | **模糊显现** | 文字出现 = 淡入 + 模糊 4 → 0，同时进行，`fast` + `easing/enter`；只作用于正在出现的那一块，出现完即撤掉模糊（不长期挂模糊效果） | 回答按句追加（每一块）；首页问候逐词显现（每词间隔 24ms，整句 ≤ 400ms；中文按系统分词 `BreakIterator.getWordInstance` 切分，英文按空格）；语音字幕由未确认变确认时（只过渡颜色与模糊 2 → 0） |
| Q3 | **进行中光带** | 状态文字上一道高光带从左扫到右：文字为原色，高光带宽 = 文字宽 40%，中心为原色 35% 不透明度（看起来更亮），两侧渐变回原色；扫过 1200ms `easing/standard` + 停 400ms，循环；只在进行中播放，结束立即停止并淡回原色 `fast`。取代现在代码里的整行明暗闪烁 | 「正在执行·第 N 步」、思考块「思考中」、「正在聆听…」 |
| Q4 | **容器变形**（卡片 ↔ 页面、球 ↔ 浮层） | 同一个容器的位置、尺寸、圆角、底色同步插值，`slow` + `easing/standard`；内容交叉淡化：旧内容在前 30% 淡出（`exit`），新内容在 30%–100% 淡入；返回反向，返回手势时跟手。用于：执行卡「查看」→ 执行详情页（圆角 28 → 屏幕圆角 → 0）；悬浮球 → 对话浮层（32 玻璃圆长成浮层，圆角 16 → 顶部 28，玻璃 → `bg/surface`）；能力卡 → 用户气泡（卡片收成气泡并移到对话顶部）；设置行 → 二级页（行标题从行内位置移动到顶栏居中标题位置，15 Regular → 15 Medium，只移动不缩放；其余内容交叉淡化） | 见左 |
| Q5 | **主按钮图标变形** | 主按钮图标不交叉淡化，而是形状连续变化（160ms `fast` + `easing/standard`）：↑ → ■：竖线从下往上收回，箭头两笔压平并下移成为方块上沿，方块从上沿向下展开并填充；■ → ↑ 反向；■ → ▶：方块右侧两角向右中点收拢成三角；▶ → ■ 反向。发送置灰 ↔ 可用只变颜色。整个 App 只有主按钮用图标变形，其他图标仍交叉淡化 | 输入框主按钮（文字与语音模式） |
| Q6 | **光球延续** | 发送后首页内容淡出时，首页光球（52）不淡出，而是沿轻微弧线缩小（52 → 16）移动到用户气泡下方执行卡标题图标将出现的位置（左 36，气泡下 16 + 16），`slow` + `easing/standard`，在那里作为「正在处理」指示等待首个事件：首个工具步骤到达 → 执行卡在它周围淡入长出，小光球即成为卡片标题的执行中指示（渐变 3s 一圈，取代加载圈）；首个事件是回答文本 → 小光球淡出 120ms，回答按 Q2 出现。完成时小光球交叉淡化为 Green ✓ | 首页 → 对话、执行卡标题、执行条、执行详情概要卡 |
| Q7 | **顶栏滚动态** | 静止在顶部时，顶栏与页面同底、无分隔线；内容一旦滚到顶栏下方，顶栏底色 `bg/canvas` 90% + 渐进模糊（上 16 → 下 0）与底部 0.5 `border/hairline` 分隔线一起淡入 `fast`；滚回顶部时淡出 120ms。标题始终居中不动 | 设置页、所有二级页、会话页 |
| Q8 | **完成的一道光** | 条件：任务用时 ≥ 10 秒，且执行卡在屏幕内。执行卡 ✓ 出现时，卡片描边上一段品牌渐变光（长度 = 周长 25%，宽 1.5）从左上角沿边框走一圈 600ms `easing/standard` 后淡出；悬浮球完成时光球亮度 1 → 1.3 → 1（600ms）。每个任务只播一次；短任务、减少动画时不播 | 执行卡完成、悬浮球完成 |

实现要点：Q1、Q4、Q6 用 Compose `SharedTransitionLayout`（跨窗口的悬浮球 → 浮层由浮层窗口以球的位置和尺寸为起点自行绘制）；Q2 用 `RenderEffect` 模糊（minSdk 34 可直接用）；Q3 用 `Brush.linearGradient` 着色文字并平移渐变；Q5 用进度参数驱动的 Canvas 绘制（或 `graphics-shapes` 的 `Morph`）；Q7 用列表是否离开顶部（`firstVisibleItemIndex > 0 || firstVisibleItemScrollOffset > 0`）触发。

### 9.4 对话主流程

| 执行卡 · 新步骤 | 新行淡入上移 6 `fast`；连接线从上一个图标向下生长 `fast`；上一步加载圈 → ✓，颜色 Indigo → Green，交叉淡化 `fast` |

| 执行卡 · 完成 → 摘要条 | 最后一步完成（小光球 → Green ✓）后停留 600ms；底部「正在…中操作·查看」行先淡出 120ms；随后卡片高度收起、圆角 28 → 24、标题行交叉淡化（小光球 → ✓；「正在执行·第 4 步」→「已完成 4 个步骤」，右侧计时 → 「用时 18 秒」），`standard`。输入框主按钮不随执行卡切换：等整次运行结束（回答输出完、播报完）才从 ■ 变回 ↑。执行中用户点过头部箭头（手动收起或展开过）则完成后不自动收起。演示见 Figma「M2」 |

| 思考块 | 思考中：「思考中」+ 思考内容按句追加（同回答）；结束：内容收起为一行「思考·2 秒」，高度 `standard`；秒数直接换 |

| 为你留意的行 | 点「整理」后按钮变加载圈 `fast`；交给 Movo 后整行按列表删除方式收起 |

### 9.6 语音

| 场景 | 动效 |
|---|---|
| 音量信号 | 所有音量动画共用一个 0–1 的平滑音量：麦克风电平按 −50 dB → 0、−10 dB → 1 线性映射，上升 80ms、回落 200ms 平滑；播报时用 TTS 输出振幅，同样平滑 |
| 语音输入（麦克风） | 麦克风底色过渡为 Indigo 浅底 `fast`，外圈随音量脉动；文字逐字写入输入框（语音转写是例外：它反映识别进度），未确认部分三级色、确认后过渡到主色 `fast`；停止时麦克风恢复 `fast` |
| 音量条（语音模式指示） | 与 `Composer/Voice` 设计一致：6 条竖条，宽 2.5、间距 2、最高 16，垂直居中；每条高度 = 16 × (0.25 + 0.75 × 音量 × 系数)，系数依次 0.375 / 0.75 / 1 / 0.625 / 0.875 / 0.5（即静态稿的 6 / 12 / 16 / 10 / 14 / 8）；每次更新 `EASE_OUT` 过渡；静音时全部停在 4（0.25），不做假动画。演示见 Figma「M4」 |
| 进入 / 退出语音模式 | 文字行与语音行交叉淡化 `standard`，工具栏原位不动：附件「+」与切回文字（键盘）原地交叉淡化，思考 / 用量 / 模型淡出；主按钮按 Agent 状态切换；字幕多行时高度同步变化 |
| 语音状态切换 | 聆听 / 播报 / 连接中：指示与状态文字交叉淡化 `fast`；字幕颜色过渡 `fast` |
| 停顿后自动发送 | 检测到停顿后，主按钮外圈出现进度环（直径 44，与主按钮同心，2 宽 Indigo，圆头，从 12 点方向顺时针），淡入 `fast`，`linear` 走完引擎的自动发送等待时长后发送：进度环淡出 120ms，主按钮 ↑ → ■（Agent 开始执行），字幕淡出 120ms 后「正在聆听…」淡入 `fast`，音量条保持聆听——输入框立即可以接着说；期间再开口，进度环淡出 120ms 并重置。演示见 Figma「M4」 |
| 播报被打断 | 用户开口即停止播报：指示交叉淡化为聆听 `fast`，音量条的信号源从 TTS 无缝换到麦克风 |
| 展开卡语音模式 | 与输入框相同：内容区交叉淡化、高度同步 `standard`，底部操作行原位不动；「已补充」停留 1.5s 后回到聆听 |

### 9.7 光球

| 状态 | 动效 |
|---|---|
| 待命 | 渐变 12s 转一圈 + 缩放 1 ↔ 1.03 呼吸（`ambient`） |
| 聆听 | 缩放跟随音量（9.6 音量信号），最大 1.12；开口说话时外圈扩散一道波纹 |

### 9.8 减少动画

触发条件：系统动画缩放为 0（`ValueAnimator.areAnimatorsEnabled()` 为 false）或省电模式（`PowerManager.isPowerSaveMode`）。**代码必须显式判断**，不能依赖系统自动缩短：无限循环在缩放为 0 时会停在某一帧，加载圈会变成一段静止的弧线，看起来像卡死。

| 原动效 | 替代 |
|---|---|
| 位移、缩放、高度变化 | 纯淡入淡出 `fast`；高度直接到位 |
| 加载圈、悬浮球状态弧 | 静态完整圆环 + 旁边文字说明进度（「正在执行·第 4 步」已有文字的不再加） |
| 小光球（执行卡、执行条、概要卡） | 静态渐变，不旋转 |
| 光球 | 静态渐变 |
| 边缘光晕 | 静态 80% 亮度，不流动 |
| 状态点光晕、音量条 | 不显示光晕；音量条停在静音高度 0.25（4） |
| 回答流式输出 | 按句直接出现，不淡入、不模糊（Q2 关闭） |
| 文字飞成气泡、容器变形、光球延续（Q1 / Q4 / Q6） | 交叉淡化 `fast`，不移动、不变形 |
| 主按钮图标变形（Q5） | 直接切换图标 |
| 进行中光带（Q3） | 静态文字，不扫光 |
| 完成的一道光（Q8） | 不播放 |
| 顶栏滚动态（Q7） | 底色与分隔线直接出现 / 消失，不淡入；模糊保留 |
| 手势指示 | 圆环直接出现，保持 300ms 后消失；滑动只显示起点和终点圆环 |
| 进度环（自动发送） | 保留（它表达等待时间，是信息而不是装饰），但改为分 4 段跳变 |

## 10. 文案

- 语气：简短、具体、口语化，像可靠的助理；不卖萌，不过度道歉。
- 按钮用动词，2–4 字：整理、提醒我、停止、接管。
- 时间：1 小时内用「5 分钟前」「42 分钟后」；当天用「15:00」；更早用「9月23日」。
- 名称：产品名 Movo；「小莫」只作为语音唤醒名，出现在语音相关界面。
- 数据来源必须说明：展示来自通知、日程、相册等个人数据的内容时，标注来源。

### 10.1 说明文字

列表页（设置、执行详情）里只有三种说明性文字，全部在卡片内，卡片外不放文字：

| 位置 | 样式 | 写法 |
|---|---|---|
| 卡内标题 `Card/Title` | `Label/Medium` 13 次要色 | 名词短语，2–6 字（「基础能力」「敏感权限」「步骤」）；右侧可放补充（三级色） |
| 行说明 | `Label/Regular` 13 次要色，紧贴标题下方 | 开关行写开启后 Movo 能做什么，动词开头（「搜索网页，打开链接并阅读正文」）；列举型写名词，最多 4 项，用顿号，不加「等」；不重复标题里的词；不加句号；一行写完（约 18 字），写不下就删字 |
| 卡片页脚 `Card/Footer` | ⓘ 14 + `Label/Regular` 13 次要色 | 写后果与保障（数据去哪、什么时候要确认）；最多 2 句，**一句一行**，句末句号 |

层级只有三档，不再加：行标题 15 Medium 主色 ＞ 卡内标题 13 Medium 次要色 ＞ 行说明与页脚 13 Regular 次要色。

断行：只在句号、逗号或意群之间换行，不拆词，一行不只剩 1–2 个字，行首不放标点；设计稿用手动换行固定断点，代码里多句说明按句拆成多个文本行。说明写给用户，不写实现词（「调用工具」「原始结果」改为「使用这些能力」「读到的内容」）。

建议在 `ui/theme` 下建立 `MovoColors`、`MovoSpacing`、`MovoRadius`、`MovoTypography`、`MovoElevation`、`MovoMotion` 六个对象，名称与本文 Token 一一对应（`bg/surface-muted` → `MovoColors.bgSurfaceMuted`）。现有 Miuix 主题色不直接用于新界面，由这些 Token 统一提供；页面代码中不出现裸写的颜色、dp 数值和动画时长。
