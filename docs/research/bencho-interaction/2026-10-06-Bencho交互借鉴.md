# Bencho 动效组件调研与 Movo 可优化交互（2026-10-06）

> 只调研、不改代码。按规范，动效改动先出 Figma 可播放稿，确认后再写代码。
> 原始数据（站点 bundle、抽出的组件目录 `catalog.json`、抽取脚本）在 `.docs/bencho-research/`。

## 结论

- **Bencho 是什么。** [bencho.dev](https://bencho.dev/) 是一个可在线调参的 React 交互组件库，作者 Lorenzo Cabra，组件 MIT 授权。分两部分：
  - **Blocks**：48 个可运行的组件，多数基于 framer-motion。
  - **Finds**：145 个从 X 上收录的他人作品，只有视频和一句说明，没有代码。
- **能借的是手法，不是组件。** Movo 是 Compose 原生应用，Bencho 的代码不能直接用。有价值的是它在每个 block 实现注释里写明的交互手法，第 2 节整理了 9 条。
- **大部分已经有了。** 对照下来，Movo 设计规范第 9 章已经覆盖了 Bencho 的多数招牌效果：复制原地变 ✓、勾选描线、分段底块滑动、光球多状态、同一容器变形、主按钮图标变形。
- **真正能补的有 6 处**，集中在三类地方：
  - App 外悬浮窗；
  - 拖动手势松手前的反馈；
  - 列表里单项的进出。

  其中 2 处属于违反现有规范，列为 P1（见第 3 节）。
- **顺带发现**：规范 §9.9 要求的完成、失败等触感，代码里都没有调用（见第 4 节）。

## 2. Bencho 实现注释里可迁移的手法

| # | 手法 | 出处（Bencho） | Movo 现状 |
|---|---|---|---|
| 1 | **一个进度值驱动整件事**：框填充、✓ 描线、删除线、文字变淡，都由同一个弹簧值换算出来，不分四个动画各自跑——多个独立过渡，总有一个会先到 | `checklist`、`sound` | Q4 容器变形是这个思路 ✓ |
| 2 | **一个对象在变，而不是两个对象交换**：搜索图标长成输入框、「+」铺开成菜单，盒子宽度就是状态，图标始终在盒子里 | `seek`、`liq-create`、`dynamic-island`、`cz-pill-cards` | Q4、Q5，展开卡从悬浮球里长出 ✓ |
| 3 | **过冲只给允许过冲的部分**：填充可以拿原始弹簧值、略超满格；✓ 和删除线要截断，否则会画过头再缩回。尺寸和圆角一起变的容器用缓动不用弹簧，否则圆角跟着晃 | `checklist`、`sound` | 规范按压用 `spring/snappy`（阻尼 1，不过冲）✓ |
| 4 | **先回应按下，展开紧跟着重叠开始**：药丸先缩 120ms，第 95ms 就开始铺开；中间停 30ms 就会被看成卡顿 | `liq-create` | §9.3.1「松手即执行，与回弹同时」✓ |
| 5 | **手势过了线就明确告知，不等松手才揭晓**：手指还按着时，越过阈值那一刻就用明显的视觉变化告诉用户「松手就会发生」；拖动越接近阈值阻力越大 `R·x/(R+x)` | `pull`、`slide-confirm` | 悬浮球移除区做到了（吸附 + 放大 + 轻触感）✓；**对话浮层下拉关闭没做 ✗**（3.2） |
| 6 | **甩出去会顺势滑行**：按松手速度投影落点，再吸附到最近的停靠点 | `image-compare`、`time-scrubber`、`rooh-wheel-carousel` | **悬浮球贴边不看速度 ✗**（3.3） |
| 7 | **控件自己就是结果**：复制框原地变「Copied!」，尺寸不变；发送卡原地变回执；删除按钮自己变成确认 | `pranav-copy-id`、`alok-sent-card`、`confirm`、`toasts` | §8.11 轻提示 ✓；**审批卡作答后、监听「停止」没做 ✗**（3.1、3.4） |
| 8 | **换字不跳宽**：两段文字叠放，容器取当前显示那段的宽度并过渡过去 | `toasts` | 「界面不跳闪」原则 ✓ |
| 9 | **只为「是」庆祝**：开启时铃铛摆动，关闭不算事件 | `toasts` | 关闭风险开关不弹确认 ✓ |

## 3. Movo 可优化的交互（建议 6 项）

以下现状描述均已在当前工作区（`feat/agent-monitor`）源码中核对。路径前缀为 `app/src/main/kotlin/io/github/fartown/movo/`。

### 3.1【P1】审批卡 / 提问卡：进退场、卡内切换、作答后的去向

**借鉴**：手法 7（`alok-sent-card`：发送后卡片原地变成回执；`adi-access-request`：通知原地展开成审批列表再收回）；手法 2。

**现状**
- App 外悬浮卡直接添加、移除窗口，没有进场和退场（`agent/runtime/AgentRuntimeService.kt:1826-1863`）。这违反 §9.5「所有浮窗先播完退场再移除」。App 内的同一张卡有进退场（`ui/components/movo/AgentInteractionCard.kt:101-125`），两处不一致。
- 锁屏时卡片会换成解锁提示：锁屏状态一变就移除整个窗口再重建（`AgentRuntimeService.kt:1815-1817`），是硬切。
- 点「允许」后卡片直接消失，用户看不到「已允许」这个结果。
- 提问卡自由输入时，发送按钮用 `if (text.isNotBlank())` 硬切出现，输入框宽度会跳一下（`AgentInteractionCard.kt:417`）。

**建议**
1. 悬浮卡与 App 内用同一套进退场：淡入 + 上移 1/3，`standard` + `enter`；退场播完再 `removeView`。
2. 解锁提示和审批内容在同一张卡里交叉淡化，高度过渡 `standard`，不重建窗口。
3. 作答后，按钮原地交叉淡化为 ✓「已允许」/「已拒绝」（`fast`），停留后卡片退场；执行卡这一步同时出现。停留时长可沿用展开卡「已补充」的 1500ms，或取更短，出稿时再定。
4. 发送按钮的位置预先留好，出现时按「图标状态切换」规则从 0.72 放大并淡入，输入框不变宽。

**备注**：审批卡界面在 Figma「候选 · 权限模式与审批规则」中尚未定稿（卡片只剩允许 / 拒绝）。建议把这几条动效作为那份稿的动效部分一起出，不单独改。

### 3.2【P1】对话浮层下拉关闭：过线即告知 + 弹簧回弹

**借鉴**：手法 5（`pull`：越过阈值是在拖动中明确告知的，而不是松手时才揭晓）。

**现状**
- 是否关闭只在松手时判断：下拉超过浮层高度的 1/3，或下甩速度大于 600dp/s（`agent/overlay/AgentResultSheetSizing.kt:50-54`、`ui/AgentConversationSheetActivity.kt:441-452`）。拖动过程中，用户不知道松手后会关闭还是弹回。
- 没过线时的弹回是固定 `SLOW` tween（`AgentConversationSheetActivity.kt:451`），不是规范写的 `spring/gentle`，也不继承松手速度。

**建议**
- 越过 1/3 那一刻给一次轻触感：`AgentHapticFeedback.Type.SWIPE` 已定义但从未调用（`agent/overlay/AgentHapticFeedback.kt:31`）。同时遮罩明显变淡一档，拖回线内时恢复。
- 弹回改用 `spring/gentle`，以松手速度为初速度。
- 侧边栏「打开到位」同理，规范已要求 `CLOCK_TICK`，见第 4 节。

### 3.3【P2】悬浮球：甩向对边

**借鉴**：手法 6。

**现状**：松手后按悬浮球中心在左半屏还是右半屏决定贴哪边，用固定 360ms 曲线吸附，不看速度（`AgentRuntimeService.kt:2076-2103`，注释写的是「`spring/gentle` 近似为 360ms standard 曲线」）。所以在左半屏把球用力往右甩，它会弹回左边。

**建议**：用松手速度投影落点，再判断左右；吸附用 `spring/gentle`，初速度取松手速度。只改这一个函数，风险低。

### 3.4【P2】后台监听列表：「停止」原地变结果、行平滑收起

**借鉴**：手法 7（`confirm`：按钮自己就是确认）；`swami-done-sinks`、`peterdev934-todo-motion`：完成的项收走，其余行补位。

**现状**
- 弹出列表用 `monitors.forEach` 渲染（`ui/components/MonitorRows.kt:257`）。点「停止」后那一行直接消失，弹层高度跳变。
- 「停止」点下后没有进行中状态。
- 「全部停止」是整行菜单，却用了实心按钮的按压（`PressKind.Solid`，`MonitorRows.kt:297`），整行会缩放。规范里列表行和菜单项只叠加、不缩放。

**建议**
- 点「停止」后，胶囊原位交叉淡化为 ✓「已停止」（`fast`，宽度不变）。随后该行按「列表增删」规则收起：淡出 120ms，高度收起 `standard`。最后一个停止后弹层关闭。
- 「全部停止」改为 `PressKind.Row`。
- 不做撤销：停止的监听重新启动不一定等价。

### 3.5【P2】输入框附件：逐个进出

**借鉴**：`zafar-upload-chips`（附件逐个落到输入框上方，各自填充缩略图）。

**现状**：图片条和文件胶囊条都用 `forEach` 平铺（`ui/components/AgentChatInputBar.kt:1195-1208`、`ui/components/AgentChatFileAttachments.kt:188-200`）。只有整条出现、消失有动画，单个添加或删除是硬切，其余项瞬间跳位。

**建议**
- 单项新增：宽度展开 `standard`，内容淡入 `fast`。
- 单项删除：先淡出 120ms，再收起宽度 `standard`，其余项平移补位。
- 缩略图解码完成时，从占位底色交叉淡化到图片（`fast`）。

### 3.6【P3】长时间步骤：显示本步已用时

**借鉴**：`kevin-agent-pill`（同时显示完成的上一步和进行中的当前步）、`cursor-dot-loaders`（每个运行中的任务都有自己的存活信号）。

**现状**：每一步的用时要等这一步结束才出现（`ui/components/ChatMessageItem.kt:4109-4118`，要求 `started` 和 `finished` 都有值）。浏览器加载、等待界面这类长步骤，执行中只有加载圈，用户分不清是慢还是卡住了。

**建议**：步骤进行超过约 3 秒后，右侧显示本步已用时。按 §9.0 第 5 条，数字直接换，不滚动；位置与完成后的用时相同，完成时原地不跳。不加新动画。

## 4. 顺带发现：规范已要求、代码未落地

这一节不是借鉴 Bencho，是盘点中发现的规范与代码差距。

**触感（§9.9）**
- App 自己调用触感的只有长按、开关 / 分段、悬浮球首次出现、拖进移除区这几处（已 grep 核对；Miuix 组件自带的不算）。
- 缺：任务完成 `CONFIRM`、执行失败 `REJECT`、开始 / 结束语音 `CONFIRM`、侧边栏打开到位 `CLOCK_TICK`。
- `AgentHapticFeedback` 目前只有 TAP / LONG_PRESS / SWIPE / RUN_STARTED 四种，需要补上确认和拒绝两类。

**硬切**

以下由子代理盘点得出，我**没有逐条复核**，动手前需要再确认：
- 输入栏：上下文用量、模型按钮用 `if` 显隐（`AgentChatInputBar.kt:689`、`:698`）；键盘 ↔ 声波图标直接换（`:576`）；语音指示用 `when` 切换（`:1341-1347`）。
- 设置行行尾内容用 `when (trailing)` 切换（`MovoSettingsRow.kt:184`）。
- 旧样式的明暗闪烁（`ChatMessageItem.kt:1833` 等，规范要求改为 Q3 光带）。
- MCP、角色、文件等列表的增删没有动画。

**不算缺口**：消息列表的 `animateItem` 关掉了移位和淡出（`AgentChatBody.kt:894-899`）。这是有意为之，代码注释写明是为了避免旧消息与新流式消息重叠，不要当缺陷改回。

## 5. 不建议引入的

| Bencho 效果 | 不引入的原因 |
|---|---|
| 所有 Hover 类（`dock`、`tilt`、`eye-tracker`、`escape`、`image-accordion` 等 9 个 block + 21 个 find） | 手机没有悬停 |
| 液态融合（`liq-create`、`liq-arrange`、`liq-toggle`、`drag-ball`、`command`、`pull` 的水滴、`one-time-code` 的融合） | Movo 视觉语言里没有液态；实现要用模糊 + 阈值滤镜，悬浮窗场景开销大 |
| 数字滚动（`like` 的计数、`caleb-day-streak`） | §9.0 第 5 条：计数与计时直接换数字 |
| 通知叠放（`alex-x-toasts`、`moiz-dismiss-toasts`、`rauno-notif-stack`） | §8.11 不用 Toast / Snackbar，结果就地反馈 |
| 背景后退或变虚（`jaimin-message-sheet`、`gabriel-share-dropdown`） | 你已否决：弹窗时背后页面不动 |
| 滑动确认、按住确认（`slide-confirm`、`jakub-hold-next`）用在付款审批或结束任务 | 付款批准后仍要在目标 App 里点按或验证身份；结束任务 09-27 已定直接结束；悬浮卡上的滑动容易与目标 App 的手势冲突 |
| 先删后撤销（`confirm`）替代删除确认框 | 与 §8.11「删除对话 / 消息用确认对话框」的定稿冲突；删一条消息会连带删后续轮次，要撤销得先做软删除。想换方向需要另出方案 |
| 粒子、彩带、揉纸、撕票（`particles`、`okazz-p5-ring`、`davidhaz-paper-crumple`、`nils-crumple-bin`、`beyza-trash-literal`） | §9.0：不做纯装饰的动效 |
| 玻璃折射 shader（Refract 标签） | 跨窗口背景模糊目前已用降级材质，GPU 开销不划算 |
| 步进器、刻度尺、环形范围（`stepper`、`time-scrubber`、`sleep`、`humidity`） | Movo 的设置选项用 `Dialog/Choice`，没有数值步进的场景 |
