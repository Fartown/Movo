## 1. Android 端 HTTP 检查器：Chucker（附 Pluto）

**核心信息模型**：一次 HTTP 调用就是一条 transaction，由 OkHttp 拦截器记录，可以在 App 内直接查看。数据有保留期限（`retentionPeriod`），也支持把敏感请求头替换成 `**`（`redactHeader`）。

**列表与详情**
- 列表项字段（来自布局文件 `chucker_list_item_transaction.xml`）：状态码 `code`（放在左侧最显眼的位置）、方法和路径 `path`、`host`、HTTPS 锁图标 `ssl`、开始时间 `timeStart`、耗时 `duration`、响应大小 `size`，GraphQL 请求还会显示操作名。
- 详情页分三个 Tab：**Overview / Request / Response**（来自 strings.xml）。3.2.0 起 Overview 里多了 TLS 版本和加密套件；4.0.0 起 JSON body 带语法高亮；body 支持搜索和高亮，4.0.0 起会自动滚到命中位置。
- 入口：常驻通知“Recording HTTP activity”，显示进行中 HTTP 活动的摘要（summary）。可以创建桌面快捷方式。主界面在独立 task 里运行，所以能和宿主 App 分屏并排看。

**过滤 / 搜索**：列表能按请求路径或响应码过滤（3.3.0）。

**导出分享**：单条可以“Share as text / Share as curl command / Share as file / Save as .har file”；4.1.0 起支持把**全部** transaction 保存为文本或 .har；body 有一键复制按钮。

**Pluto**（打开过它的 GitHub 首页）：插件式框架，包含 Network、Exceptions & Crashes、Logger 等插件，入口是通知。首页说 Network 插件能分享和转成 cURL，Logger 插件有搜索和过滤。插件 README 里没写列表字段，所以更细的交互**未核实**。Flipper 未调研。

**值得借鉴的 3 点**
1. 列表行采用“状态码色块 + 路径 + 耗时 / 大小”的三段式紧凑布局，一眼就能看出成功还是失败、慢不慢。
2. 详情页分“概览 / 请求 / 响应”三个 Tab，概览只放结论（状态、耗时、TLS），原始内容放到后面的 Tab。
3. 常驻通知作为入口，加上“单条 / 全部”两级导出（文本、cURL、HAR）。

- https://raw.githubusercontent.com/ChuckerTeam/chucker/develop/CHANGELOG.md

## 2. Android Studio Logcat（新版）

**核心信息模型**：每条日志包含日期、时间戳、进程 / 线程 ID、tag、包名、优先级（FATAL / ERROR / WARNING / INFO / DEBUG / VERBOSE）和消息。官方原文是“不同 tag 有各自的颜色”。

**列表**：Standard 视图显示全部字段；可以在 “Configure Logcat Formatting Options” 里切到 **Compact** 视图，显示的信息更少。默认不换行，可以开 Soft-Wrap。默认会**自动滚到最新**：用户点击日志区或向上滚动时自动跟随关闭，点 **Scroll to the End** 恢复。工具栏可以清空、暂停、重启 Logcat。支持 Split Right / Split Down 分屏，也可以开多个 Tab。

**过滤 / 搜索（查询语法）**
- `tag:` `package:` `process:` `message:`；`level:ERROR` 匹配“该级别及更严重”的日志；`age:5m` 只看最近 5 分钟；`is:crash`、`is:stacktrace`；`package:mine` 表示当前项目的包。
- 字段名前加 `-` 表示取反（`-tag:MyTag`），字段名后加 `~` 表示正则（`tag~:My.*Tag`）；支持 `&`、`|` 和括号。
- 可以通过 Show history 查看历史查询，打星收藏；`name:` 能给收藏的查询起名。

**导出分享**：官方页面没提到导出（**未核实**）。“折叠重复行 / 折叠堆栈”在该页面上也没找到（**未核实**）。

**值得借鉴的 3 点**
1. `level:` 按“该级别及以上”过滤，比“只看异常”这个二元开关粒度更细。
2. 用户一滚动就暂停跟随，并提供按钮回到最新：日志持续刷新时也能停下来仔细看。
3. 提供 Standard / Compact 两种密度切换，以及结构化查询和收藏查询。

来源：https://developer.android.com/studio/debug/logcat

## 3. Chrome DevTools Network 面板

**核心信息模型**：一个请求就是一行。默认列有 Status、Type、Initiator、Size、Time，外加 Waterfall 列。

**列表**：Waterfall 列可视化每个请求的时间分布，官方原文是“颜色较浅的部分是等待时间，较深的部分是下载字节的时间”；可以按开始时间、响应时间、结束时间、总时长、延迟排序。顶部有 Overview 时间轴；Big request rows 模式会显示更多细节；被拦截的请求在表格里标红。

**详情 Tab**：Headers / Payload / Preview / Response / Timing。Timing 按阶段拆分：
- Queueing、Stalled
- DNS Lookup
- Initial connection（原文：“包括 TCP 握手或重试以及协商 SSL”）
- Request sent
- Waiting (TTFB)：等待响应的第一个字节
- Content Download

**过滤 / 搜索**
- 按类型快速过滤：All、Fetch/XHR、JS…
- 属性过滤：`status-code:404`、`is:running`、`larger-than:`、`has-response-header:`
- Invert 反选；More filters 里有 Blocked requests、3rd-party requests 等
- Cmd/Ctrl+F 在请求头和响应体里全文搜索
- **Preserve log**：页面重新加载后仍保留请求记录

**导出分享**：Copy as cURL（可以复制单个请求，也可以复制一组请求）；Save all as HAR（有脱敏和含敏感数据两个版本）；Import HAR。

**值得借鉴的 3 点**
1. 每行一条迷你瀑布条，扫一眼就能看出串行、并行和慢请求。
2. Timing 按阶段拆分，与 Movo 现有事件几乎一一对应：dns → connecting → tls → request_sent → first_byte（TTFB）→ 流式下载 → closed。
3. 状态过滤支持反选，导出区分“脱敏 / 含敏感数据”。

来源：
- https://developer.chrome.com/docs/devtools/network/reference
- https://developer.chrome.com/docs/devtools/network

## 4. LLM / Agent 追踪：Langfuse 与 LangSmith

**Langfuse 信息模型**：trace 代表一次请求或操作（例如一轮对话）；observation 是其中的每一步（LLM 调用、工具调用、检索等），可以**嵌套**，形成与实际执行一致的树；多个 trace 可以归入 session（例如一个聊天线程）。observation 有 10 种类型：event（离散事件）、span（有时长的工作单元）、generation（模型生成，含 prompt、token、成本）、agent、tool、chain、retriever、evaluator、embedding、guardrail。

**Langfuse 级别与状态**：observation 有 DEBUG / DEFAULT / WARNING / ERROR 四个级别和 `statusMessage`；单个 trace 内可以**按级别过滤** observation。

**Langfuse 时间线与耗时**：Timeline 视图（2024-06 上线）以时间线图展示 agent 流程，用来“定位延迟瓶颈、看清并行、理解深层嵌套的多步推理”。2024-10 起，父 span 显示子节点**汇总后的**延迟和成本；打开 `%` 按钮后，子节点占总量 ≥75% 标红、50–75% 标黄。

**LangSmith**
- 概念：run 是一个工作单元（例如一次 LLM 调用）；trace 是一次操作包含的全部 run；thread 由多个 trace 组成，代表多轮会话。
- 视图：Trajectory / Turns / Details 三种，快捷键 `T` 和 `D`。Details 显示输入输出、耗时、错误和子 run。
- 瀑布图：changelog 写明，悬停瀑布条会显示开始 / 结束时间、**首 token 时间**、token 和成本明细。
- 分享：可以生成公开链接，也可以把 thread 下载成 Markdown。

**值得借鉴的 3 点**
1. 按 trace → 子节点的树组织日志，父节点汇总耗时、状态和 token。
2. 占比着色（≥75% 红、50–75% 黄），自动指出最慢的环节。
3. 树视图和时间线视图可以切换；悬停或点按显示 TTFT、token 等摘要；支持导出为 Markdown。

- https://langfuse.com/changelog/2024-06-12-timeline-view

## 5. Sentry：Breadcrumbs 与 Trace View

**Breadcrumbs**：记录问题发生**之前**的事件轨迹。每条 breadcrumb 的字段是 type、category、message、data、level（fatal / error / warning / info / debug）和 timestamp。type 分为 default、debug、error、navigation、http、info、query、transaction、ui、user，官方原文说它们“在 UI 中有各自的颜色 / 图标”，部分颜色和图标会根据 category 渲染（具体对应关系**未核实**）。UI 抽屉里可以搜索（匹配 type、category、message、data）、**按 type 和 level 过滤**、排序，时间可以显示为绝对时间或相对时间；原文说相对时间为负数时，表示该事件发生在列表最上面那条之前。

**Trace View**：瀑布结构，按时间和父子关系排列（子 span 挂在父 span 下）。左侧是操作列表，右侧是时长以及该时间段内发生的错误等事件。能高亮某一行并通过 URL 分享；链路断开的子树用虚线表示。自动分组和折叠在页面中没有写到（**未核实**）。

**值得借鉴的 3 点**
1. 为错误保留“前情”：打开一次失败时，自动带出它之前的 N 条系统事件（网络断开、切到后台等）。
2. 按“类别 → 图标 / 颜色”建立映射（http、lifecycle、voice、network、error），同时按类别和级别两个维度过滤。
3. 支持相对时间显示（相对 run 开始的 +ms），配合“链接 / 高亮到某条”进行分享。

来源：
- https://docs.sentry.io/product/issues/issue-details/breadcrumbs/
- https://develop.sentry.dev/sdk/data-model/event-payloads/breadcrumbs/
- https://docs.sentry.io/concepts/key-terms/tracing/trace-view/
- https://docs.sentry.io/product/explore/trace-explorer/

## 对 Movo 运行日志的借鉴清单（按优先级）

| # | 建议 | 具体做法 | 借鉴自 |
|---|---|---|---|
| P0-1 | **按 Run → Request → 事件三级分组，替换扁平卡片流** | 顶层每个 run（R1…）一行摘要：状态、总耗时、请求数、错误数；展开后是 Q1、Q2…；再展开才是 http.* / sse.* 细粒度事件。系统事件（生命周期、前台服务、语音、网络）作为独立分组，或按时间插入到 run 之间 | Langfuse trace / observation 树、LangSmith run / trace、Sentry Trace View |
| P0-2 | **Request 行做成 Chucker 式紧凑三段** | 左侧状态色块（http_status 或错误码 code），中间是模型 / endpoint 和 stage，右侧是 duration_ms 和 received_bytes；重试次数用 “×2” 角标 | Chucker 列表项 |
| P0-3 | **请求内阶段瀑布（Timing 分解）** | 用已有事件计算：DNS → Connect → TLS → Request sent → 等待首字节（TTFB）→ 首个 SSE 事件 → 流式接收 → closed，画成一条横向分段条；详情页里每段标出毫秒数 | Chrome Timing / Waterfall |
| P0-4 | **错误优先 + 级别色标** | 事件分为 error / warn / info / debug 四级，行首用 4dp 色条（红 / 橙 / 默认 / 灰）；有错误的 run 和 request 默认展开并置顶提示；attempt.failed → retry.scheduled 链路用红色连线串起来 | Logcat 级别、Langfuse level、Sentry level |
| P0-5 | **“只看异常”升级为筛选 chips** | 级别 chips 采用“该级别及以上”语义；类别 chips：模型请求、SSE、重试、生命周期、前台服务、语音、网络；状态 chips：成功 / 失败 / 进行中 / 已重试；支持反选 | Logcat `level:`、Chrome 过滤和 Invert、Sentry 按 type/level 过滤 |
| P1-6 | **跟随最新 + “有 N 条新日志”提示** | 默认跟随最新；用户上滑后暂停跟随，底部浮出“N 条新日志 ↓”，点击回到最新 | Logcat Scroll to the End |
| P1-7 | **紧凑 / 标准密度切换** | 紧凑模式每个事件单行显示（时间 + 图标 + 事件名 + 关键字段），标准模式展开字段表；默认用紧凑，替代现在的大卡片 | Logcat Compact 视图 |
| P1-8 | **一键导出分享** | run 级、request 级、全部三种粒度；格式为 Markdown 或纯文本（便于贴到 issue）和 JSON；敏感头默认脱敏，可选“含敏感数据”；通过系统分享面板发出 | Chucker 四种分享方式、Chrome 两种 HAR、LangSmith 下载 Markdown |
| P1-9 | **详情页分 Tab：概览 / 时间线 / 原始字段** | 概览放结论（状态、总耗时、TTFB、首个 SSE 事件时间、重试次数、错误码及说明）；时间线放阶段瀑布；原始字段放 key-value 并支持复制 | Chucker Overview / Request / Response、Chrome 详情 Tab |
| P1-10 | **按类别区分图标 / 颜色，时间显示可切换** | http、sse、retry、lifecycle、foreground-service、voice、network 各用一个图标；时间可在绝对时间和相对 run 开始的 +ms 之间切换 | Sentry breadcrumbs |
| P2-11 | **慢环节占比着色** | 在 run 内，某个 request 或阶段占总耗时 ≥75% 标红、50–75% 标黄，直接指出瓶颈 | Langfuse `%` 着色 |
| P2-12 | **错误的“前情”上下文 + 结构化搜索** | 打开失败请求时，附带它前 N 条系统事件（例如 network lost、切到后台）；搜索支持 `code:`、`status:`、`run:R3` 等简单前缀 | Sentry Breadcrumbs、Logcat 查询语法 |

**建议的落地顺序**：先做 1→2→4→5，把分组、紧凑行、错误优先和筛选建成页面骨架；再做 3 和 9，补充请求详情和阶段瀑布；最后做 6、8、7 这些可用性增强，以及 10–12。
