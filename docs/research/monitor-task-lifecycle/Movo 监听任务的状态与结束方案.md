# Movo 后台监听：任务状态与结束交互方案（待 review）

日期：2026-10-06。状态：已定稿（Figma「22 · 监听任务的状态与结束」，规范 8.1 / 8.12 / 9.5），代码在分支 `fix/monitor-lifecycle`。实现与本方案的差别：展开卡每行写「已触发 N 次」（监听是一条命令，下一次什么时候来不一定知道，不写「下次」）；语音口令只认「结束任务」，「别提醒了」交给 Movo 自己判断（多个监听时先问停哪个）；常驻通知的「结束任务」结束所有监听。

## 0. 一页看懂

**你遇到的问题**
- 让 Movo「每 3 分钟提醒我喝水」，它开了监听、这一轮就答完了。之后悬浮球显示绿环 ✓（完成），可监听还在跑。
- 你点悬浮球上的「结束任务」，结束的只是正在跑的那一轮，监听照旧每 3 分钟唤醒 Movo。

**为什么会这样**
- 10-05 定稿的规范 8.12 照 Claude Code 的 Monitor 做：「一轮」和「监听」是两回事。
  - 一轮答完就算完成；
  - 监听只能从输入框的「监听」胶囊、常驻通知的「全部停止」、提醒通知的「停止提醒」去停。
- Claude Code 这样分是因为开发场景里的后台任务（开发服务器、日志跟踪）本来就要比一轮对话活得久，按 Esc 只取消当前这一步。
- Movo 的监听是你交代的一件事，在你心里它就是任务本身。

**推荐的改法**

| | 现在 | 改后 |
|---|---|---|
| 任务是什么 | 一轮对话 | 你交代的这件事：这一轮加上它开的监听。监听还在，任务就没完 |
| 监听等待下一次事件时，悬浮球 | ✓（完成） | **监听中**：琥珀色整环加时钟角标，不转 |
| 事件把 Movo 叫醒、它在处理时 | 悬浮球多半还是 ✓ | **执行中**：靛蓝弧线转动，处理完回到监听中 |
| 监听到时限自然结束 | — | 任务做完了，和其他任务一样留 ✓；你自己结束的不留 ✓，回到待命 |
| 点悬浮球「结束任务」、常驻通知、语音「结束任务」 | 只停这一轮 | 这一轮和这个对话里的监听一起结束；5 秒内可以撤销 |
| App 里的停止键 ■ | 只停这一轮 | 正在跑的是这个监听任务的一轮，就一起结束（可撤销）；是你在同一个对话里问的别的事，只停那个回答 |
| 只停其中一个监听 | 输入框「监听」胶囊、提醒通知「停止提醒」 | 不变 |

**要你定的两件事**（详见第 4 节）
1. 结束时怎么防误触：先确认，还是直接结束、可以撤销（推荐撤销）；
2. App 里停止键的范围：按归属（推荐），还是一律连监听一起停。

## 1. 现状（代码核实）

**结束入口**

| 入口 | 停什么 |
|---|---|
| 悬浮球展开卡「结束任务」 | 只取消当前这一轮（`AgentRuntimeService` → `cancelRun`），不碰 `MonitorRegistry` |
| App 里的停止键 ■ | 只取消当前这一轮 |
| 语音「取消任务」 | 只取消当前这一轮 |
| 常驻通知 | 两个按钮：「停止」只停这一轮（`ACTION_STOP`），「全部停止」连监听一起停（`ACTION_STOP_ALL`） |
| 输入框「监听」胶囊 → 列表 | 停单个监听，或「全部停止」 |
| 提醒通知「停止提醒」 | 只停这一个监听 |

**悬浮球状态**
- 一轮结束时直接按完成处理：显示 ✓，或回到待命。不看这个对话还有没有监听在跑。
- 监听把 Movo 叫醒的那一轮（后台轮）不接管悬浮球，悬浮球停在上一个状态（比如 ✓）；只有要操作其他 App 时才接管。

**App 里**
- 执行卡头写「已完成 N 个步骤」；
- 监听只体现在输入框的「监听」胶囊和对话里的事件行。

## 2. 参考

| 产品 | 做法 | 能借鉴的 |
|---|---|---|
| Claude Code（官方文档） | Esc 只取消当前这一步，后台任务、Monitor 继续跑，这一轮算结束；用 `/tasks` 或桌面端「Watch background tasks」面板单独查看、停止；Monitor 默认 5 分钟、最长 30 分钟 | 「一轮」和「后台任务」分开，适合开发工具；**不适合**你把监听当成任务的场景 |
| 常见撤销设计（Gmail 撤销发送、iOS 删除照片进「最近删除」等） | 能恢复的操作不先问，做完给一段撤销时间 | 结束监听可以晚 5 秒真正生效，期间能撤销 |

## 3. 方案

### 3.1 任务与状态

**任务** = 你这次交代的事：开始这件事的那一轮、它开的监听、以及监听把 Movo 叫醒处理事件的那些轮。任务的状态如下：

| 状态 | 什么时候 |
|---|---|
| 执行中 | Movo 正在为这个任务干活：开始那一轮，或事件叫醒的一轮 |
| 监听中（新增） | 没有在干活，但还有监听在等下一次事件 |
| 已暂停 | 不变 |
| 完成 / 失败 | 这一轮结束，而且这个对话里没有监听在跑了 |

**各处表现**

- **悬浮球**
  - 执行中：不变（靛蓝弧线）。
  - 已暂停：去掉灰环和球体变灰，只留右上角深色暂停角标（10-06 你定的）。
  - 监听中：琥珀色整环加时钟角标，不转。琥珀色和时钟图标沿用规范 8.12 里监听的颜色与图标。
  - 事件叫醒的一轮：不管操作不操作其他 App，都接管悬浮球、显示执行中。边缘光晕仍然只在操作其他 App 时出现。
  - 「常驻悬浮球」关着时：任务在监听中也显示悬浮球，因为任务还没完。
- **展开卡**
  - 监听中点球弹出：标题「监听中·喝水提醒」（两个及以上写「监听中·2 个」），右侧「17:00 结束」，下一行「已提醒 3 次·下次 15:33」（两个监听时一行一个），操作行右侧「结束任务」。不另起「全部结束」：任务本来就包括监听，执行中、监听中、常驻通知都叫「结束任务」，同一个词同一个意思。
  - 执行中：不变，「结束任务」按 3.2 的结束规则处理。
- **App 里的执行卡头**
  - 开了监听的那张卡，监听还在时写「监听中·喝水提醒」（琥珀色时钟，同事件行），不写「已完成 N 个步骤」；
  - 监听都结束后，换回「已完成 N 个步骤」。
  - 输入框的「监听」胶囊保留。
- **常驻通知**
  - 正文「监听中·喝水提醒·17:00 自动结束」；
  - 只留一个按钮「结束任务」（全部结束），不再分「停止」和「全部停止」。

### 3.2 结束

**一个原则：你说「结束」，就是结束这件事。**

| 入口 | 改后 |
|---|---|
| 悬浮球展开卡「结束任务」（执行中、监听中都是这个按钮） | 这一轮（如果在跑）和这个对话里的监听一起结束 |
| 常驻通知「结束任务」 | 同上 |
| 语音「结束任务」「别提醒了」 | 同上，Movo 念一句「已结束，喝水提醒也停了」 |
| App 里的停止键 ■ | 第 4 节第 2 项 |
| 「监听」胶囊里的「停止」、提醒通知「停止提醒」 | 只停那一个监听，不变 |

**结束后的反馈**
- 展开卡原位换成「已结束，喝水提醒也停了·撤销」，5 秒后收回；悬浮球回到待命。
- App 里对话最后插一行「已结束任务·喝水提醒·15:10」，后面跟「撤销」，5 秒后「撤销」消失、这行留下；输入框的「监听」胶囊同时去掉。
- 撤销：监听在这 5 秒内并没有真正停掉，撤销就照常继续；已经取消的那一轮不恢复，下一次事件会正常叫醒 Movo。

### 3.3 不变的

- 监听的启动方式、事件行、结束行、时长上限、设置项，都按规范 8.12。
- 暂停：只暂停正在跑的这一轮；暂停期间到达的事件排队，等继续后处理。

## 4. 要你定的事

1. **结束时怎么防误触**

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 直接结束 | 一点就全部结束 | 最简单 | 误触后监听没了，要重新交代一遍 |
| **B 直接结束 + 5 秒撤销（推荐）** | 一点就结束，5 秒内可撤销 | 想结束的时候不多一步；点错了能救回来 | 要做撤销提示 |
| C 先确认（你提的） | 有监听时弹「同时结束 2 个监听？」，点「全部结束」才结束 | 不会误触 | 每次结束都多一步，而你点结束时多半就是想结束 |
| D 让你选 | 弹「只停这一轮 / 全部结束」 | 两种都能做 | 每次都要想一下，「只停这一轮」也很少用 |

我倾向 **B**：结束是你的主动操作，多数时候确认是多余的；而监听停掉以后能晚 5 秒生效，误触可以无代价撤回，比确认框更省事。

2. **App 里停止键 ■ 的范围**

| 方案 | 做法 |
|---|---|
| **A 按归属（推荐）** | 正在跑的是这个监听任务的一轮（开监听的那一轮，或事件叫醒的一轮），就一起结束（可撤销）；你在同一个对话里另问别的事，■ 只停那个回答，监听不动 |
| B 一律一起停 | 在有监听的对话里按 ■，都连监听一起结束（可撤销） |

我倾向 **A**：在同一个对话里问点别的、想打断回答时，不该把提醒也停了。
