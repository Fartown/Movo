# Movo「当前时间」位置与提示缓存方案（第 3 版，已定）

日期：2026-10-06。状态：已定（10-06）：时间放在请求末尾，同时把上一次任务的模型原始输出原样存下来，两件一起做；代码在分支 `feat/prompt-cache-env`。实测脚本和原始数据：`.docs/prompt-cache/`。

**第 3 版改了什么。** 第 2 版要把时间消息存进历史，牵扯存档、压缩、编辑重发，太重了。这版改成**每次请求都把时间放在最末尾、不存**，只改请求组装一处。实测缓存和存进历史一样，行为也没变差。

## 0. 一页看懂

**问题。** 每次任务，系统提示末尾都带一句「当前时间：2026-10-06 星期二 12:34」，精确到分钟，所以每次都不一样。提示缓存只认「从头开始一模一样的部分」，工具定义（约 7000 token）和全部对话历史都排在这句后面，所以每次新任务都要从这里往后重新算。

**改法（两件）。**
1. 系统提示里不放时间。每次发请求时，在 `input` 的**最末尾**（你这句话、工具结果之后）加一条开发者消息「环境信息……当前时间……」。这条消息不存历史，也不进压缩、检查点、对话存档。
2. 上一次任务的模型原始输出（思考、调用编号等）随历史存档，下一次任务里服务商和模型都没变就原样发出（1.5）。

**为什么这样就够。** 时间在最后，它后面没有别的内容。下一次请求时它换成新时间、挪到新的末尾，前面的历史、工具调用和结果都还在原位，缓存照常命中，只损失它自己约 100 token。

**效果（默认模型实测）。**

| 情况 | 现在 | 改后 |
|---|---|---|
| 只有问答的对话，下一次任务命中 | 20% | **96%** |
| 上一次任务调过工具（真模型跑 6 步，约 2.8 万 token），下一次任务命中 | 9% | **96%**（只做第 1 件是 42%，断点见 1.5） |
| 约 4 万 token 的长对话，模型耗时 | 3.0 秒（不命中） | 2.4 秒（命中） |
| 问时间、算日期、不该提时间时不提（8 个场景各 10 次） | 76 次直接答对，4 次去调终端查时间 | 79 次直接答对，1 次去调终端 |

**你会感觉到的变化。** 长对话里每次任务快大约半秒；按量计费的服务商上，输入费用大幅下降。回答内容不变。

## 1. 现状（代码核实）

1. **时间在哪。** `AgentPromptBuilder.environmentLine()` 生成，每次任务算一次，作为最后一条系统消息（`AgentPromptBuilder.kt:169-178`，`AgentModelClient.kt:116`）。
2. **系统消息怎么进请求。**
   - Responses：system / developer 消息都拼进 `instructions`（`OpenAiRequestMessages.kt:28-44`），`input` 里不出现（`ResponsesRequestBuilder.kt:54`）；
   - Chat Completions：合并成开头一条 system；
   - Anthropic：合并进 `system` 字段。
3. **`instructions` 一变，后面全部不命中**（`.docs/voice-brevity/eval/cache_probe.jsonl` E0），工具顺序本身是固定的（`ToolRegistry.kt:11`）。
4. **为什么当初放在系统消息里**（`.docs/full-review-1005/findings.md`）：
   - D1：时间加在用户消息开头，模型当成你新说的话，主动报时、乱调工具；
   - T1-E1：模型偶尔把时间写进你让创建的文件，所以有「它不是任务内容」这句。

   这次时间不进用户消息，是单独一条写明来源的开发者消息，见 3.2 的行为实测。
5. **另一个断点（第 2 件改它）。** Movo 任务结束存历史时，会丢掉模型的原始输出项（思考、调用编号等），下一次任务重建成另一种格式发出（`ResponsesEphemeralState.kt:6`，`ResponsesRequestBuilder.kt:65-87`）。意思一样，模型照样能用，但缓存逐字比对，会断在上一次任务的第一次模型输出，只到 42%。

## 2. 方案

| 改哪 | 怎么改 |
|---|---|
| `AgentPromptBuilder` | Responses 路径不再把时间放进系统消息；时间文字照旧生成，随请求交给组装那一步 |
| `ResponsesRequestBuilder` | 组装 `input` 时，在最末尾追加一条 `role = developer` 的消息，内容就是现在那句时间，**一字不改**（含「不要主动报时」「它不是任务内容」） |
| 时间什么时候算 | 每次任务开始算一次，同一次任务里各步都用这一个（就算任务跨了一分钟也不变） |
| 存档、压缩、检查点、编辑重发 | 都不动：时间不在消息数组里 |
| Chat Completions、Anthropic | 不改，时间仍在系统提示里，和现在一样（第 6 节第 2 项） |
| ChatGPT 订阅 | 用同一个 Responses 组装，自动受益 |
| 模型原始输出存档（第 2 件） | 助手消息存档时带上这一步的原始输出项，并记下服务商、地址、接口和模型（`ResponsesEphemeralState.origin`，不含密钥）。下一次任务组装历史时，四项都一样就原样回放，不一样（换了模型、换了服务商）就照现在重建 |
| 不再脱敏（第 3 件，10-06 定） | 原来读文件、记忆、设备信息、设置、通知、剪贴板、MCP 等工具的参数和结果存历史时换成占位文字（`AgentSensitiveToolPolicy`），这次整段去掉，原样存、原样重放。理由：这些内容在读到的那次任务里已经发给了模型，存档时再藏起来防不住模型；不该给模型的内容应在工具这一层就不返回。Codex、Claude Code 也都原样保存。顺带：缓存不再在这些步骤断开，下一次任务也能直接用上次读到的结果 |
| 上下文压缩 | 照现在丢掉原始输出项（摘要改变了前缀，旧输出项不再对得上） |
| 旧存档 | 没有原始输出项，照现在重建，兼容 |

语音段仍是 `instructions` 的最后一条，不受影响。时间挪走后，语音轮和语音轮之间整段命中；文字轮和语音轮之间仍断在 GFM 段（语音方案 2.4）。

**不做的事。**

| 做法 | 为什么不做 |
|---|---|
| 时间存进历史（第 2 版） | 缓存和放末尾一样（3.1），却要改存档、压缩、编辑重发 |
| 只给日期、精确时间让模型自己查（Codex、Claude Code 的默认） | 不会答错，但模型经常先去终端查时间，多一轮调用（3.3）。分钟级时间放末尾每次只多约 100 token，几乎没有成本 |
| 放在你这句话前面、不存（第 1 版） | 下一次任务时它从中间消失，上一次任务的工具循环每次重算（调过工具时 73%，放末尾没有这个问题） |

## 3. 实测

条件：打包默认模型（方舟 Agent Plan，Responses），真实系统提示和 36 个工具。

### 3.1 缓存

| 场景 | 放法 | 命中（中位） |
|---|---|---|
| 纯问答：两轮问答 + 上一轮，问新问题，时间晚 6 分钟（`cache_env.py`、`cache_env5.py`，各 3–6 次） | 现在 | 20% |
| | 放末尾、不存 | 96%（6 次里 1 次 83%，按缓存块取整） |
| | 存进历史（参考） | 96% |
| 上一次任务调过工具：真模型跑「打开设置，搜索蓝牙」6 步，再问「看一下 Wi-Fi」（`cache_env3.py`、`cache_env4.py`，各 3 次） | 现在 | 9% |
| | 放末尾、不存 | 42% |
| | 存进历史（参考） | 43% |
| | 放末尾 + 模型输出原样存（第 6 节第 1 项） | 96% |

### 3.2 行为（`env_eval3.py` → `env_eval3.jsonl`，每个场景 10 次）

| 场景 | 现在 | 放末尾 |
|---|---|---|
| 「现在几点了」答 12:34 | 10/10 | 10/10 |
| 「距离元旦还有几天」（86 或 87 都算对，口径不同） | 8/10，2 次调终端 | 9/10，1 次调终端 |
| 「明天是星期几」 | 10/10 | 10/10 |
| 「介绍一下火星」不提时间 | 10/10 | 10/10 |
| 「新建 note.txt，内容写：买牛奶」文件不带时间（T1-E1） | 10/10 | 10/10 |
| 有历史时「看一下系统版本」只调相关工具（D1） | 10/10 | 10/10 |
| 上次答过 08:00，再问「那现在几点」答 12:34 | 9/10，1 次调终端 | 10/10 |
| 历史里聊过几轮后算元旦 | 9/10，1 次调终端 | 10/10 |

没有一次答错时间。「调终端」是模型自己去查了日期，不算错，单独记。

### 3.3 只给日期行不行（`env_eval4.py` → `env_eval4.jsonl`，每个场景 10 次）

把那句改成只到日期（「今天：2026-10-06 星期二」，并说明要几点几分就用终端 `date` 查），和现在的分钟级对比，只看模型的第一次回应：

| 场景 | 分钟级（现在） | 只给日期 |
|---|---|---|
| 「现在几点了」 | 10/10 直接答 | 10/10 先调终端查 |
| 「距离元旦还有几天」 | 9/10 直接答，1 次查 | 5/10 直接答，5 次先查 |
| 「明天是星期几」 | 10/10 | 10/10 |
| 「半小时后提醒我喝水」（倒计时，不用知道几点） | 10/10 | 10/10 |
| 「下午三点提醒我开会」 | 10/10 直接设闹钟 | 3/10 直接设，7 次先查现在几点 |
| 「介绍一下火星」不提时间 | 10/10 | 10/10 |
| 「新建 note.txt」文件不带时间 | 10/10 | 10/10 |

只给日期没有答错，但模型经常多查一轮，每次多一次模型调用，语音里尤其明显。所以保留分钟级，放末尾。

### 3.4 速度（`latency_long.json`）

约 4 万 token 的对话：命中 2.4 秒，不命中 3.0 秒。对话越长收益越明显。

## 4. 怎么验证

- **单测**：
  - `instructions` 不含时间；`input` 最后一条是时间消息；同一次任务各步的时间文字一样；
  - 存档、压缩结果里没有时间；
  - Chat Completions、Anthropic 的请求和现在逐字一致。
- **实测回归**：用改后的真实请求跑 `cache_env4.py`、`env_eval3.py`，结果不低于 3.1、3.2。
- **小米真机**（独占设备）：同一对话里连问三件事，从运行日志 `usage_received … cache=` 看每次任务第一次请求的缓存数；「现在几点」「明天早上七点叫我起床」「新建文件写买牛奶」结果正确、文件干净。

## 5. 工作量

从 main 新开分支：改代码加单测约 1 小时；实测回归约 20 分钟；真机约 1 小时。

## 6. 已定的事（2026-10-06）

1. **模型原始输出原样存：一起做。** Responses 的原始输出（含思考；ChatGPT 订阅还有加密思考）存进本机对话存档；换模型时退回重建。
2. **范围：只改 Responses 这条路**（默认模型、内置 OpenAI、ChatGPT 订阅），Chat Completions 和 Anthropic 不动。
3. **存历史不再脱敏，一起做。** 能给模型的内容就原样存；该保密的在工具层不返回，不靠存档时脱敏。

## 7. 单独提出的问题（不在本次范围）

- Anthropic 路径完全没有提示缓存（没设 `cache_control`）。它允许在用户消息之后放 system 消息，时间放末尾的做法也适用，但要用 Claude 的 Key 实测。
- 内置 OpenAI 的 Responses 路径没设 `prompt_cache_key`；上下文压缩、推荐追问用的是随机 key（`AgentProvider.kt:47`），可以顺手改成对话 id。
