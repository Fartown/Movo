# 电视端 Agent 设计调研：语音为主、按遥控器操作

- 日期：2026-10-07
- 范围：TCL 55F295C（Android 9）上的 Movo 电视版；评审现有工具和提示词，给出电视 Agent 该做哪些事、每类事怎么实现、工具怎么设计
- 性质：调研与方案草案，**没有改代码**；方案经你 review 同意后再拆实施
- **10-07 用户定的原则**：以通用方法为主干，也就是安卓标准接口，加上像人一样按遥控器、看屏幕；**不用各视频 App 自带的语音接口**；每个 App 一套的私有深链、写死的按键流程，不作为方案主体。下文按此修订中，工具设计会结合真机按键矩阵（T4）整体重写
- 证据（都在 `.docs/tv-agent-design/`）：
  - `evidence-runs.md`：真机运行记录里的用户原话、失败案例、耗时、设备能力
  - `tv-model-view.md`：电视版模型实际收到的提示词和工具定义（原样导出在 `render/`）
  - `external-research.md`：业界电视语音助手和遥控注入的外部调研

## 0. 结论

1. **现在的电视 Agent 是「手机 GUI Agent 去掉触屏」**。它读无障碍节点，再对节点做聚焦和点击，方向键、确认键、菜单键一个都发不出去。提示词是手机版的，上面打了一层电视补丁。所以模型在电视上做多步操作很笨：
   - B站搜「罗翔」14 轮后失败；
   - 爱奇艺搜《西游记》播第 1 集用了 30 轮、212 秒；
   - 快进 60 秒要 8 轮、76 秒（脚本要求每步核实，轮数偏多），人按遥控器只要 1–4 秒。
2. **语音下用户要办的事，大部分不该经过界面操作。**
   - 找片播放、播放控制、音量、打开应用、电视本身的设置、问答，这些都应该**一句话、一次工具调用**办完，背后走安卓标准接口（媒体会话、系统音量、启动应用）和遥控按键。
   - 业界没有一家靠模拟遥控器去完成「一句话直达」，界面操作只做兜底（§3）。
   - 按用户 10-07 定的原则，只用通用法：安卓标准接口，加上像人一样按遥控器。各 App 的私有语音接口、私有深链、按 App 写死的流程都不作为主体（§4）。
3. **需要在界面里操作时，像人一样按遥控器。**
   - 工具发真实按键。这台 TCL 上实测有两条路：
     - 系统自带的「多屏互动」服务，电视自己连自己就能发方向、确认、返回、主页，不用用户授权；
     - 本机 ADB，100/100 成功，单次约 30 毫秒。
   - 观察以「焦点在哪、上下左右是什么」为中心。
   - 「把焦点走到目标上」这种确定的控制回路交给工具自己做，模型只决定目标。有个电视导航基准（TVWorld，港大与 TCL 研究院）的结果可以佐证：最强的通用模型逐键导航，成功率也只有 60–66%。
4. **提示词按电视重写**，不再沿用手机提示词再打补丁：
   - 去掉约 1.1–1.3k token 的手机内容，以及指向不存在工具（`skill_read`、`ask_user`）的说明；
   - 每轮把「电视现在在放什么」直接给模型；
   - 加一条出口：不是对 Movo 说的话就不回应。
5. **工具按「管什么」分开，每个工具内部合并通道**（§6）：
   - 按键工具只管屏幕导航；
   - 播放控制、音量各自一个工具，内部先用标准接口，不行再按键，都要回读确认；
   - 静音、暂停不用「切换」。
   
   业界都是这么分的；真机也证明让模型自己按键去控制播放会出错（芒果按 ENTER 弹开会员，爱奇艺按左右键弹 VIP）。
6. **优先级**：
   - 先修播放控制和音量（现在 38% 的播放控制没得到确定成功，一半是工具自己的问题）；
   - 再上按键通道和焦点观察；
   - 提示词重写和评测集贯穿始终。

## 1. 现状评审：为什么「蠢」

按根因归成 6 类。每条带证据，细节见 `.docs/tv-agent-design/` 里的两份报告。

### 1.1 操作方式照搬手机，按不了遥控器（影响最大）

| 现象 | 根因 | 证据 |
|---|---|---|
| 提示词说「方向键移动焦点、确认键选择」，但工具里没有方向键和确认键 | `ui_key` 在电视上只有 back、home（`UiKeyTool.kt:53`）；Android 9 的无障碍没有 `GLOBAL_ACTION_DPAD_*`；电视没有 Root，`input keyevent` 那条路被 `noRoot` 关掉（`TvToolProviders.kt:12`） | `tv-model-view.md` §5.4 |
| 模型在「点」和「聚焦」之间来回打转 | `ui_tap` 遇到不可点的节点，提示「请改用焦点操作」（`AgentAccessibilityService.kt:456`）；`ui_focus` 只是 `ACTION_FOCUS`，聚焦不等于按确认，这条路走不通 | P6 |
| 自绘界面看不见 | 云视听极光整个首页只有 1 个节点；B站首页只有 ViewPager；TCL 桌面 8 张卡片全是没有文字的 `FrameLayout` | `evidence-runs.md` §5.4 |
| 动作经常因为「页面变了」失败 | 轮播和焦点放大会不停改窗口内容，观察编号很快失效；B站 4 次 `NOT_ACTIONABLE` | C6；P25 |
| 搜索框打不了字 | 奇异果、酷喵的搜索用的是自绘字母键盘，不是可编辑框；提示词却要求「按屏幕键盘逐个输入」，每个字母要「操作 + 观察」两轮 | C7；P28 |

### 1.2 工具粒度太低：每件事都拆成十几轮

- 找片到播放最少要 `video_search → 观察 → 点 → 观察 → 点 → 等 → 查状态`，6–8 轮起步。
- 每轮模型 2–3 秒；推理 token 多时一轮 6–11 秒。
- 本地模拟（`.docs/agent-perf-review/lane2/tv_sim_v2.log`）给出的对照：

  | 做法 | 「放狂飙」轮数 | 模型耗时 |
  |---|---|---|
  | 现在的工具 | 8–12 | 13–21 秒 |
  | 动作结果直接带回观察 | 5 | 8–9 秒 |
  | 一个复合工具 `video_play` | 1–2 | 1.5–2.9 秒 |

### 1.3 该有的直达工具缺了，或者不全

| 用户说 | 现在怎么做 | 缺什么 |
|---|---|---|
| 「静音」「小点声」 | 只能设成绝对百分比，也读不到当前音量；真人说「声音小一点」被调成了 30→50 | 静音开关、相对调节、读当前音量 |
| 「放第 8 集」「跳到 20 分钟」「从头放」 | 只能在界面里一步步点 | 选集、跳到绝对时间、从头播 |
| 「明天要不要带伞」 | 读不到位置（7 次全失败），网页搜索每次塞进约 4 万 token，答案前后矛盾，最长念了 68 秒 | 所在城市、天气工具 |
| 「这是谁演的」「这集还剩多久」 | 模型得先查状态再搜索 | 每轮直接告诉模型正在放什么 |
| 「切到 HDMI」「一小时后关机」 | 做不了 | 电视本身的控制（需要按键通道） |

### 1.4 工具结果不可信

- `video_search` 在优酷搜不到时也返回成功（只核对了片名有没有出现在屏幕上）。
- `ui_wait.gone=true` 被忽略：本想等文字消失，文字还在就返回「等到了」。
- `ui_observe.query`、`ui_scroll.until_text` 两个参数在后端没有实现。
- `media_control`：
  - 广告期间返回假状态；
  - 换集后 media_id 不刷新；
  - 前台不是播放器时，会读到别的 App 的会话（真机读到过 B站）。
- 校验失败时返回旧错误格式，和提示词教的 `status/retry` 对不上（P11）。

### 1.5 提示词：手机提示词加补丁

完整原文见 `tv-model-view.md` §3。固定开销约 7.0k token。

- **指向不存在的工具**：
  - 每轮注入 3 个内置 Skill 的索引，要求「先调用 skill_read」，可电视上没有这个工具（P1）；
  - 打字轮要求「用 ask_user 提问」，电视上也没有（P5）。
- **手机内容约 1.1–1.3k token**：相册、短信、通话记录、发消息确认、Root、剪贴板等（P19、P20）。
- **前后矛盾**：
  - 回答长度三处说法不一致；
  - 记忆是先读还是先写，两处说法相反；
  - 什么时候重新观察，也有正反两种说法（P8–P10）。
- **补丁堆叠**：`TvPromptProfile` 一段话里塞了 redacted 占位（已过时）、截图 schema 怎么读、自绘键盘、搜片核对、`app_open` 的 reply、朗读长度，都是针对一次次具体失败加的，模型拿不到一个整体的做事思路。
- **缺电视当前状态**：模型不知道前台是什么、在放什么、音量多少，所以「暂停」「下一集」「这是谁」都得先多调一轮工具。
- **没有「不是对我说的」出口**：环境声、节目台词被识别成指令（13 句），模型每句都认真作答，真正的问题反而被顶掉（C1）。

### 1.6 语音会话层（不属于工具，但直接影响「显得蠢」）

- 后到的语音会覆盖前一个还没念出来的答案（C1）。
- 推理 token 偏多：deepseek flash 开推理时，一轮输出 820–1484 个 token，用时 6–11 秒（C7）。

## 2. 语音下，用户在电视上要办哪些事

真机材料里**没有一条真人语音是找片或播放控制**：真人只说过问时间、调音量、要静音，其余都是测试句和脚本。所以下表的频率参考业界公开数据和常识，**需要上线后用真实数据校准**。

| # | 类别 | 典型说法 | 频率 | 期望做法 | 期望时延（说完 → 生效） |
|---|---|---|---|---|---|
| A | 找片播放 | 「放狂飙」「看三体电视剧第 5 集」「继续看昨天那个」「放点小猪佩奇」「周星驰的电影」 | 最高 | 一次工具调用直达播放 | ≤10 秒，不含片头广告 |
| B | 播放控制 | 「暂停」「继续」「快进一分钟」「跳到 20 分钟」「下一集」「放第 8 集」「从头放」「跳过片头」「倍速」「清晰度调高」 | 高 | 媒体会话直接控制，不行再发播放器按键 | ≤2 秒 |
| C | 音量 | 「大点声」「小一点」「静音」「调到 20」 | 高 | 系统音量接口 | ≤2 秒 |
| D | 打开应用、导航 | 「打开 B站」「回首页」「返回」「退出」 | 中 | 启动应用、发返回或主页键 | ≤3 秒 |
| E | 电视本身 | 「切到 HDMI1」「一小时后关机」「关电视」「画面亮一点」「连蓝牙耳机」「现在连的什么 Wi-Fi」 | 中低 | 按键加厂商菜单的固定流程，或系统、厂商接口 | ≤5 秒 |
| F | 问正在看的东西 | 「这是谁演的」「这剧讲什么」「这是第几集」「还剩多久」「这首歌叫什么」 | 中 | 播放信息直接给模型，再加搜索 | ≤4 秒开始说 |
| G | 问答 | 「明天要不要带伞」「几点了」「XX 是什么」 | 中 | 天气接口、搜索；所在城市问一次就记住 | ≤4 秒开始说 |
| H | 界面代操作（所见即可说） | 「往下翻」「选第二个」「点进去」「把那个弹窗关掉」「换到电影频道」 | 中，作为兜底 | 读焦点和屏幕，按遥控器 | 每步 ≤3 秒 |
| I | 对话管理 | 「别说了」「行了退下」，以及不是对 Movo 说的话 | 高（隐性） | 本地口令、`end_call`、不回应 | 立即 |

几点判断：

- **A、B、C 占大头，又都能直达。** 这三类做好了，语音体验就过关一大半，而且这三类不该让模型看屏幕。
- **H 是兜底，不是主路。** 业界的「所见即可说」也是这样：电视助手主要靠内容和接口直达，界面代操作只用在这些接口覆盖不到的地方。
- **I 决定了「像不像人」。** 电视开着时屋里的人声、节目台词一直在，Agent 不能对每句话都作答。

## 3. 业界怎么做

详细内容和 250 多条来源见 `.docs/tv-agent-design/external-research.md`。每条都标了可信度：【官方】【论文】【二手】【推测】。下面只列和设计直接相关的。

### 3.1 一句话直达：意图加深链或媒体会话，不点界面

| 产品 | 做法 | 可信度 |
|---|---|---|
| Alexa（Fire TV） | Video Skill 把「片名、季、集、类型、指定平台、原话」整理成 `SearchAndPlay` / `SearchAndDisplayResults` 交给 App；播放控制走 `PlaybackController` / `SeekController`。Alexa+ 是「API 优先，界面自主操作补充」 | 官方 |
| Google TV | 内容目录或搜索 provider 给出深链 → 带起播参数打开 → 之后用 MediaSession 控制。2026 年的 Android 智能体路线是「AppFunctions 优先，界面自动化兜底」 | 官方 |
| 小米智能屏 Launcher | 每个视频 App 一个适配器，统一成 `startVideo / next / select(集) / seek / setResolution / skipStart`，外加一组「支持哪些能力」的声明；腾讯把**用户原话**直接交给腾讯自己的语音代理；再用无障碍按 view id 判断是不是在播 | 二手（反编译） |
| 腾讯叮当 TVS | 公开了视频领域的意图表：按集播放、快进快退、定位播放、倍速、清晰度、第几个、翻页、按演员搜 | 官方（腾讯 GitHub） |
| 奇异果 | App 内置了供厂商语音调用的服务，事件包括跳到某时间、相对跳转、搜索、按关键词选（所见即可说）、选第几个、选集、按键 | 二手（反编译）；**本机注册了这个服务（实测 dumpsys）** |
| 国内厂商（小米、TCL、华为、海信） | 找片靠厂商自己的聚合媒资库，不在 App 里打字搜索；结果页说「第一部」「看第二个」，按「从左到右、从上到下」编号 | 官方 + 二手 |

**对我们的含义**：

- 播放控制、音量这类按意图设计的工具是对的。参数可以参照 Alexa：片名、类型、季、集、指定 App、原话。
- 厂商能「一句话直达」，靠的是和各 App 的商务对接、私有协议。我们拿不到这些，按用户定的通用法也不走这条路（§4）。

### 3.2 电视上的直达深链都要内容 ID

- 五个 App 都有私有的「直接播放某集」入口（极光 `tenvideo2://?action=7&cover_id=`、奇异果 `igala://…/play` 和 `ACTION_PLAYVIDEO`、芒果 `mgtvapp://vod/player`、小电视 `yst://`、酷喵 `ykott://tv/detail`）。都没有官方文档，都要内容 ID。
- 从公开样例看，这些 ID 和各家网页版是同一套。可行链路是「片名 → 联网解析出各平台 ID → 深链直达」，省掉电视上最慢的打字搜索和挑结果。
- 本机已存的 dumpsys 里能看到奇异果的 `igala` play/detail 入口和芒果的 `TclIntentParseActivity`。都还没在这台 TCL 上用真实 ID 跑过。
- **按通用法，这条路不作为方案主体**（属于各 App 私有逻辑）。是否作为可选加速，见 §10 D6。

### 3.3 遥控器和焦点

- Android 9 上，普通应用全局发方向键、确认键**只有本机 ADB 一条路**。无障碍的方向键要 Android 13，菜单和播放暂停键要 Android 16。自带输入法发的键只送到前台窗口，系统键无效。【官方】
- 手势点击会让系统进入触摸模式，焦点高亮可能消失。电视上应少用手势。【官方】
- 业界的自动化测试工具（stb-tester、Roku WebDriver）都是「代码循环：按一次 → 回读焦点 → 偏了纠正」，不让人或模型逐键决策。【官方】
- 读焦点：
  - 有无障碍节点时用 `findFocus(FOCUS_INPUT)`；
  - 自绘界面用按键前后截图的差异，再加视觉模型找高亮框。【官方 + 推测】

### 3.4 「所见即可说」

各家（Alexa UIController、Tizen、DuerOS、AliGenie）的约定都是两部分：

- 屏幕条目列表：每条带序号、标题、别名、是否焦点、能做的动作；
- App 当前处在什么页面：首页、列表、详情、播放、搜索、设置。

序号约定 1 = 第一个、0 = 当前、-1 = 最后（Tizen）。第三方 App 不会给我们上报这些，要自己从无障碍树或截图生成，就是 §5.2 的 `ui_observe`。

### 3.5 语音交互

| 原则 | 来源 |
|---|---|
| 回复一两口气读完，细节交给屏幕 | Alexa 设计规范【官方】 |
| 确认分三档：大多数隐式确认（回答里带出理解到的参数，用户可以顺口纠正）；只有难以撤销的操作才显式确认；「停止」「取消」不确认 | Google 对话设计【官方】 |
| 别过度反问：即使有歧义，排第一的候选 77% 是对的 | Amazon 2021【论文】 |
| 超过 4 秒体验明显下降；慢的时候先说一句前导语能改善感受 | CUI 2025【论文】 |
| 节目声音、旁人聊天、不是对助手说的话，调用空操作工具 `wait_for_user`，不出声 | OpenAI 语音提示词指南【官方，已核对原文】 |
| 全屏播放时不开连续对话 | 华为智慧屏【官方】 |
| 电视语音查询平均只有 2.04 个词 | Comcast【论文】 |

### 3.6 工具设计通用规则

来源：Anthropic、OpenAI、Google ADK【官方】。

- 按工作流合并成少数高层工具，开局可见的工具少于 20 个；
- 返回语义化、带编号的结果，不返回内部 ID；
- 返回里带状态和可执行的错误说明；
- 参数尽量用枚举；
- 工具名和描述必须和实际工具列表一致，否则模型会编造工具。我们的 `skill_read`、`ask_user` 问题正是这一条；
- 用评测迭代工具描述。

## 4. 通用法：标准接口 + 像人一样按遥控器

用户 10-07 定了原则：要考虑通用法；不调各 App 自带的语音接口；每个 App 一套的私有逻辑不作为方案主体。下面只用两类对任何 App 都成立的手段。

```
用户一句话
   │
   ▼
模型（带「电视现在的状态」：前台 App、页面类型、在播什么、音量）
   │
   ├─ 标准接口：启动应用、媒体会话、离散媒体键、系统音量 ── 能确认就一次办完
   │      │ 不支持，或做完回读确认不了
   │      ▼
   └─ 遥控：按键、读屏幕、把焦点走到目标、屏幕键盘输入 ── 「按一下、看一下」，直到确认
```

- **标准接口**是安卓给所有 App 定的约定：
  - `MediaSession` 的播放、暂停、跳转、上下一条；
  - 离散媒体键：播放 126、暂停 127；
  - `AudioManager` 的音量和静音；
  - 启动应用的 LEANBACK 入口。
  
  好处是快、能回读；问题是国内 App 实现得残缺（T4：B站会话什么都不支持，芒果进度恒为 0，腾讯退到后台还报在播）。所以**做之前先读状态，做之后按用户的意图回读，确认不了就换遥控**。
- **遥控**是每个电视 App 都必须支持的：没有它，用户就用不了这个 App。但按键的效果取决于 App 和当前焦点，各家不一致（T4：确认键在芒果没反应，ENTER 会弹开会员；左右键在 B站是 ±10 秒，在爱奇艺免费片上先弹 VIP 提示）。所以遥控一律**「按一下、看一下」**：
  - 每次按键都带回屏幕变化；
  - 步长这类数值在运行时测出来，不写死；
  - 出现开会员、付款类页面就停下并说明。
- **不做**：
  - 各 App 的私有语音接口；
  - 按 App 写死的按键流程；
  - 单个 App 的自定义动作。
  
  现有代码里属于私有逻辑的有两处：`video_search` 的三家搜索深链、`media_control` 里奇异果专用的跳转和换集动作。去留见 §10。
- **组合工具也只由通用步骤组成**。比如找片播放 = 打开 App → 进搜索 → 输入片名 → 在结果里选中 → 选集 → 确认在播。每一步都用通用工具完成，不认具体是哪个 App。第一期先让模型用这些通用工具一步步做，量出轮数和耗时；嫌慢再把同样的步骤包成一个 `video_play`，包装后不新增任何按 App 区分的逻辑。

## 5. 遥控器：按键怎么发出去

### 5.1 可选通道

| 通道 | 能做什么 | 这台电视上的状态 | 限制 |
|---|---|---|---|
| **本机 ADB → shell 常驻进程** | 任意按键（方向、确认、菜单、信号源、数字、媒体键）、截图、`am start` | **已实测**（P0 报告 #3、#4）：应用自带 RSA 密钥，一次授权后连接约 100 毫秒；100 次按键全部收到，单次 P50 30 毫秒；能取到 1920×1080 截图 | ① 用户要先在 TCL 设置里打开网络调试，第一次在电视上点「允许」；② **完整重启后 TCL 会关掉 ADB**（`/init.usb.rc` 开机把 `persist.sys.service.adbd.enable` 置 0），需要用户重新打开，原授权保留；待机唤醒不受影响 |
| TCL「多屏互动」协议（TCP 6553，按键包 `149>>键码`、文字包 `155>>文本`） | 方向、确认、返回、主页（菜单键是否送达没能判断）；文字能写进 TCL 自绘搜索框 | **10-07 实测**（`.docs/tv-agent-design/probes/T1/report.md`）：`com.tcl.MultiScreenInteraction_TV` 在跑；连 127.0.0.1 被拒（只监听局域网 IP）；**电视自己连自己的局域网 IP:6553 可以**，握手约 0.1 秒，没有任何确认框；方向键、确认、返回、主页都生效 | ① 电视要有局域网 IP（断网就不能用）；② 文字包只成功写入第一次，之后不再追加，字母会变大写，原因没查清；③ 不用 ADB、不用用户授权，重启后是否照常可用还没测（它是系统服务，推测可以）；④ 无鉴权，同网段任何设备都能控制这台电视，这是 TCL 自身的现状 |
| 无障碍：节点聚焦和点击、手势点按 | 有节点的界面能点；手势点按在极光的搜索入口实测进入过搜索页 | 现状 | 不是按键；自绘界面、Leanback 行切换、自绘键盘常常不响应；手势会让系统进入触摸模式，焦点高亮可能消失 |
| 自带输入法发键 | 方向键、确认键（只送到前台窗口） | 未验证 | 要用户把默认输入法切成 Movo；系统键（主页、信号源）发不了。只作为 ADB 不可用时的备选 |
| 无障碍 `GLOBAL_ACTION_DPAD_*` | 方向键、确认键 | Android 13 才有，本机没有 | 以后的新电视可以直接用 |
| 厂商 SDK `TSDK_adb_setADBEnable` | 开机自动重开 ADB | 源码里看到了，需要厂商证书授权，没调通 | 要和 TCL 合作 |

**建议**：

- TCL 电视上主通道改用 6553 协议（实测可用，不需要用户打开调试）。还要再测两件事：Movo 自己的进程连上后发键是否同样生效；这些按键会不会被 Movo 的按键过滤当成用户按键，触发「你来操作」让出。
- 本机 ADB 常驻进程作为备用，也是非 TCL 电视上的主选。
- 两条都没有时退回无障碍，遥控能力会打折扣。设置页要明确显示「遥控能力：可用 / 需要打开网络调试」，并说明怎么打开。

ADB 注入的按键**不经过 Movo 的按键过滤**（`evidence-runs.md` §5.2）。这正好区分了两种按键：Agent 自己按的键不会被当成用户按键而触发「你来操作」让出；用户按真遥控器，照旧让出。6553 发出的键会不会经过过滤还没测；如果会经过，Movo 要识别出是自己刚发的键并放行。

### 5.2 观察：以焦点为中心

人看电视界面时只关心三件事：焦点在哪、它周围是什么、屏幕上有哪些能选的东西。`ui_observe` 现在给的是一大串节点 JSON（0.2k–2.8k token，33–39% 是冗余字段），没有 `selected`、`focusable`，卡片标题也没有聚合进来。

建议的电视观察结果（示意，奇异果搜索结果页）：

```text
应用：银河奇异果 · 搜索结果
焦点：「播放」按钮（属于结果卡「狂飙 · 39集全」）
  上：结果卡「狂飙」  下：「狂飙·速看纯享版」  左：左侧导航「搜索」  右：「选集」
屏幕上能选的（按行）：
  [1] 狂飙（39集全，张译 张颂文）  [2] 播放 ●焦点  [3] 选集
  [4] 狂飙·速看纯享版  [5] 罚罪  [6] 围猎  [7] 勇者无惧  [8] 猎罪图鉴2
  左侧导航：[9] 搜索 [10] 首页 [11] 会员中心 …
```

实现要点：

- **卡片标题聚合**：可点的容器自身没有文字时，取子节点文字作标题。TCL 桌面的 8 张卡片、奇异果的「播放」按钮都是这种情况。
- **按行分组、去掉父子重名**：编号「从左到右、从上到下」，和 TCL 小T的结果页一致。用户和模型都能说「第二个」「下一行第一个」；「这个」指当前焦点。
- **标出页面类型**：首页、列表、详情、播放、搜索、设置。各家的「所见即可说」都带这一项，模型据此判断「下一集」该走播放控制还是界面。
- **上下左右的邻居**：按几何位置算出四个方向最近的可选项。它和真实的方向键焦点走向不一定一致，只作为参考，以按键后的回读为准。
- **节点太少时自动附截图**：可选项少于阈值，或没有焦点信息时，自动附一张缩到长边 1280 的截图，并把焦点框画出来。来源用 ADB 截图或助理截图。视频画面区域会是黑的，这一点要在结果里说明，避免模型误以为没在播。
- **每次按键的结果直接带回新焦点和变化**，不用再单独观察一轮。

### 5.3 「走到目标」由工具做

现在模型每移动一步焦点都要「动作 + 观察」两轮。改成：模型给目标（观察里的编号或文字），工具在内部循环——看当前焦点 → 按目标所在方向发一个方向键 → 回读焦点 → 直到焦点落到目标上（或者确认走不过去）→ 需要时再按确认。

- 方向和步数先按节点位置估算（AOSP `FocusFinder` 的规则：同一条线上的优先，再比加权距离）。列表和 Leanback 网格会改写焦点走向，所以每按一步（或已知等宽列表的一小批）都回读焦点，偏了重新规划。
- 按一次没有任何变化就判定为无效键，换方向或按返回，不重复按同一个键。TVWorld 总结的失败模式之一，就是卡住时反复按同一个无效键。
- 按下和抬起成对立即发出，不能按住不放：Android 9 长按判定是 500 毫秒，按住会触发长按或加速滚动。
- 自绘界面没有焦点节点时，第一版只能把截图交给模型判断；第二版再用按键前后截图的差异定位焦点框。
- 每次调用设上限（例如 15 步）。走不到就返回「停在哪、为什么」，不要无限按。

## 6. 工具设计

依据：

- 业界工具划分调研：`.docs/tv-agent-design/key-vs-semantic-tools.md`；
- 真机按键矩阵：`.docs/tv-agent-design/probes/T4/report.md`；
- `media_control` 失败归因：`.docs/tv-agent-design/mediactl-analysis/report.md`。

工具措辞最终按评测定稿（项目惯例），本节给结构和示意。

### 6.1 合并还是分开：按「管什么」分开，每个工具内部合并通道

**结论：按领域分成「按键 / 播放 / 音量」等几个工具；每个工具内部把能用的通道合在一起，按顺序自己选。不按通道分（不要一个「媒体会话工具」加一个「按键工具」，两边都能暂停）。**

理由：

1. **业界没有一家合并。** Alexa、Google、SmartThings、Home Assistant、Roku、HomeKit、小米 MIoT，都把「按键」和「播放 / 音量 / 输入源」拆成不同接口。面向语音和模型的那一层，按键只管屏幕导航：
   - Alexa 的按键接口只有方向、确认、翻页、返回等 12 个键，没有播放和音量；
   - Home Assistant 干脆不给模型按键工具。
2. **真机上，用按键做播放控制既不可靠也有风险。** T4 实测：
   - 确认键在 B站、爱奇艺是暂停，在芒果没反应，ENTER 还会弹「开通会员」；
   - 左右键在 B站一下 10 秒，在爱奇艺免费片上第一下是弹 VIP 提示，焦点停在「按 OK 键开通 VIP」上。
   
   让模型自己按键去暂停、快进，迟早会点进付费页。
3. **功能重叠的工具会让模型选错。** 研究里相似工具是错选的主要来源（MetaTool、AndroidControl 里「返回」有 23.9% 被预测成点屏幕上的返回按钮）。按键工具里不放播放、音量、静音键，模型就**没有机会**用错。
4. **只有语义工具也不行。** 「往下翻」「选第二个」「把弹窗关掉」、陌生 App、语义工具失败后的兜底，都只能靠按键。

**切换类操作不给模型。** 「静音」「暂停」都要显式说目标状态。Home Assistant 把 toggle 从模型工具里删掉时的原话是 "It only confuses"。这台电视上静音键（164）是切换键，按两次就取消了；我们现在「静音 = 音量设 0」也不对，取消静音后回不到原来的音量。

### 6.2 工具目录

| 工具 | 管什么 | 不管什么 | 内部通道（按顺序） | 返回 |
|---|---|---|---|---|
| `ui_key` | 在屏幕上移动和选择：上、下、左、右、确认、返回、主页、菜单、数字 0–9；可连按几次 | 播放、暂停、快进快退、音量、静音（不在枚举里） | 遥控按键通道（§5.1） | 实际按了哪几下、在哪一步停下及原因、按完后的前台 App、页面类型、焦点和四周、屏幕上新出现的东西 |
| `ui_observe` | 读当前屏幕 | — | 无障碍节点；节点太少时附截图 | §5.2 的格式 |
| `ui_tap` | 把焦点走到屏幕上的某一项，可选再按确认（「选第二个」「点进去」） | 同 `ui_key` | 代码内闭环：按一下、回读焦点、纠偏（§5.3） | 最终焦点；没走到时停在哪、为什么 |
| `ui_input` | 在当前搜索框里输入文字 | — | 可编辑框直接写入 → 系统文字输入通道 → 在屏幕键盘上逐字走键 | 框里回读到的文字 |
| `media_control` | 正在播放的视频：读状态、暂停、继续、快进 N 秒、后退 N 秒、跳到某时间、从头播、上一集、下一集、第 N 集 | 屏幕上的焦点移动 | 见 §6.4 | 操作前后的片名、集数、进度、播放状态，实际走的通道，是否回读确认 |
| `volume_set` | 设到某值、大点声、小点声、静音、取消静音、读当前音量 | 播放 | `AudioManager`：设值、加减一档、`ADJUST_MUTE` / `ADJUST_UNMUTE`（重复调用无副作用）；不注入静音键 | 调整前后的音量和是否静音 |
| `app_open` | 按名字或别名打开应用 | — | LEANBACK 启动入口 | 是否到了前台；找不到时的相近候选 |
| `wait_for_user` | 这句话不需要回应（节目声音、旁人聊天） | — | — | 结束这一轮，不出声 |
| `end_call` | 用户要结束对话 | — | — | 已有 |
| `weather`、`web_search`、`memory_*` | 问答、记住所在城市和偏好 | — | — | 见 §6.7 |

找片播放第一期不单独设工具，由模型用 `app_open → ui_key / ui_observe → ui_input → ui_tap` 完成，量出效果后再决定要不要包成 `video_play`（§4）。

### 6.3 遥控器上的键各是什么作用（`ui_key` 用法分节的依据）

下表左边是安卓电视的通用约定（Android TV 设计规范和质量指南），右边是这台 TCL 上实测的差异。**结论是：除了「方向键移动焦点」和「返回退一层」比较一致，其他键的效果都因 App、因状态而异，所以工具每按一下都要把屏幕变化带回来，模型以实际变化为准。**

| 键 | 通用约定（在菜单、列表里） | 通用约定（全屏播放时） | 这台电视实测 | 放进 `ui_key` 吗 |
|---|---|---|---|---|
| 上 / 下 / 左 / 右 | 焦点移一格 | 左右：快退、快进一小步；上下：调出信息栏或选集栏。控制栏隐藏时，第一下常常只是把控制栏调出来 | 列表里一致。播放时 B站左右 ±10 秒、自动生效；爱奇艺免费片上第一下先弹 VIP 提示 | 是，但用法分节写明「播放中的快进后退用 `media_control`」 |
| 确认 | 打开或选中焦点项 | 暂停 / 继续 | B站、爱奇艺：暂停加控制栏；芒果：没反应；在广告、会员提示上按会进付费页 | 是；结果里出现付费页时停下说明 |
| 返回 | 退回上一层，关掉弹层 | 先收起控制栏，再按可能弹「退出播放？」 | 爱奇艺有三层：关面板 → 弹「退出不看了 / 继续观看」→ 关提示 | 是 |
| 主页 | 回到电视桌面 | 同左，离开播放 | 回 TCL 桌面 | 是。用户也会说「按一下主页」，和其他工具不重叠 |
| 菜单 | 当前 App 的选项菜单（规范不要求 App 必须支持） | 清晰度、倍速、比例等 | 在 Movo 设置页看不出变化；其他 App 未测 | 是 |
| 数字 0–9 | 直播换台；个别选集页可以直接输集数 | — | 未测 | 是 |
| 音量 + / − | 系统音量一档 | 同左 | 安卓电视上音量键不送给前台 App，由系统处理；范围 0–100，一档多少未测 | **否**，用 `volume_set` |
| 静音 | 切换静音（按两次就取消了） | 同左 | 未测；AOSP 把 164 固定转成「切换静音」 | **否**，用 `volume_set` 的静音 / 取消静音 |
| 播放 / 暂停 / 快进 / 快退（媒体键） | — | 对应动作 | 126 / 127 在爱奇艺、腾讯、芒果有效，B站无效；遥控器上没有这几个物理键 | **否**，作为 `media_control` 内部的通道 |
| 信号源 | 打开信源菜单 | — | 能打开 TCL 信源菜单（P0） | 否。切信号源之前定了不做（Q12） |
| 电源 | — | — | 关了无法远程唤醒 | **否**，任何工具都不发 |

### 6.4 `media_control` 怎么做才「生效」

现在的问题（详见 `mediactl-analysis/report.md`）：只有媒体会话一条路，成败标准比用户要的更严，不幂等，会选错 App。34 次动作里 13 次没得到确定的成功，其中 7 次是工具自己的问题。改法：

1. **只管前台 App 的播放器。** 会话所属 App 和前台不是同一个时（T4：腾讯退到后台仍报在播），返回「现在没有在播放，前台是 X」。不去控制后台的 App。
2. **先读状态再动作。** 已经是目标状态就直接返回成功：说暂停时已经暂停，就回答「已经暂停了」。
3. **通道顺序**（都是通用手段）：
   1. 会话声明支持该动作 → `MediaSession`：`pause`、`play`、`seekTo`、`skipToNext`；
   2. 离散媒体键：暂停 127、播放 126；
   3. 播放器里的按键，按「按一下、看一下」：
      - 快进、后退：先按一下右键或左键，读出进度变化，得出这个 App 一下跳几秒，再按需要的次数；跳的秒数在运行时测，不写死。按完出现会员、付款提示就停下，按返回关掉，报告「这个片子不能快进（会员限制）」；
      - 选集：调出选集栏，用 `ui_tap` 选「第 N 集」；找不到就把屏幕情况交回模型。
4. **按用户的意图判断成没成**：
   - 快进 60 秒 → 进度前进了大约 60 秒就算成，播没播不管；
   - 下一集 → 标题或界面上的集数变了就算成，不依赖 App 不填的 `media_id`。
5. **进度从哪读**：会话的进度在走、和时间对得上就用它；不可信时（T4：芒果恒为 0，爱奇艺播放中不准，腾讯 5 秒才更新一次）读屏幕上的进度文字。
6. **广告**是能预知的状态：明确返回「片头广告还剩约 N 秒，结束后才能控制」，不能只说「不支持」。
7. **去掉 `toggle`**，动作都用显式目标。

**10-07 下午补测（`probes/T4b/report.md`，主测腾讯和 B站）对上面的修正：**

- **静音**：
  - 静音键 164 确认是切换键，按一次静音、再按一次恢复。
  - shell 下没有幂等的静音命令：`media volume --adj mute` 不支持，`cmd media_session volume` 不可用。
  - App 内 `AudioManager.adjustStreamVolume(ADJUST_MUTE)` 还没测。如果它也不行，就只能「先读 `Muted` 状态，不一致才按 164」。
- **音量**：一档 ±1（0–100 刻度）。所以「大点声」要由工具定一个合理步长，例如一次调 5，不能按一下键就算。
- **腾讯**：
  - 播放中左右键的效果无法归纳（单按、连按的净变化都不稳定），**不能用按键快进**；
  - 媒体会话的进度可信（误差约 1 秒），暂停、播放重复发不会反转。所以腾讯走媒体会话：跳转用 `seekTo`，暂停用 `pause`；
  - 详情页默认焦点在「SVIP 免费看全片」，不能盲按确认。
- **B站**：
  - 会话什么都不支持，进度恒为 0，播放时截图是空的；
  - 右键一下约 +10 秒。快进只能靠按键，进度只能读界面文字，而 `uiautomator` 读一次又太慢。
- **「按一下、看一下、算次数」不成立**。改成「每按一下读一次进度，间隔不短于 3 秒，读不到进度就停下并告诉用户」。B站这类没有会话的 App，快进只能做到「大约」，回答里要如实说明。

**语音会话（movo-74）10-07 隔离重测，证明「看屏 → 模型思考 → 点节点」这条路在 B站上根本走不通**（`.docs/tv-main-verify/isolated-retest/`，R188、R189）：

- 「打开哔哩哔哩，搜索罗翔」跑了 3 次：1 次成功（22 轮、90 秒），2 次转圈（64 轮、340 秒；另一次 19 轮后被系统杀掉）。
- 根因：云视听小电视首页约 4 秒没有操作，就会切成全屏预览，顶部导航消失，节点从约 50 个变成 1–2 个。
- 看屏后 3.5 秒内点按的都成功了，超过 4.4 秒的全部失败。可一轮模型就要 4–10 秒，所以每次都晚一步。
- 顶部按钮是没有文字的容器，模型还误点进过「年卡限时加赠」购买页。

这正是 §5.3「走到目标由工具在内部闭环完成」的理由：读屏和按键必须在同一个工具调用里紧挨着做完，不能隔一轮模型。

### 6.5 描述和用法分节（示意，措辞用评测定稿）

按项目规范：描述只写契约，何时用、何时不用写进随工具注入的分节，不夹英文。

| 工具 | 描述（契约） | 用法分节要点 |
|---|---|---|
| `ui_key` | 按遥控器的方向、确认、返回、主页、菜单或数字键，可以连按几次。返回按完后的页面、焦点和屏幕上的变化。 | 只用于在屏幕上移动和选择：往下翻、往左、确认、返回上一页、回主页。播放、暂停、快进后退、换集用 `media_control`，音量、静音用 `volume_set`。各 App 对按键的反应不同，以返回的变化为准；没变化就换个键或先读屏幕，不要反复按同一个键。 |
| `media_control` | 控制前台正在播放的视频：暂停、继续、快进或后退若干秒、跳到某时间、从头播、上一集、下一集、第几集，或读取播放状态。返回操作前后的片名、集数、进度，以及是否确认生效。 | 用户说暂停、继续、快进 30 秒、后退一分钟、下一集、第 8 集、从头放，都用它，不要用按键代替。「后退 / 快退」带时间是跳转；不带时间的「返回」是返回上一页，用 `ui_key`。 |
| `volume_set` | 设置或调整电视音量，静音或取消静音。返回调整后的音量和是否静音。 | 静音、取消静音、大点声、小点声、调到 20 都用它。静音时调大音量会自动取消静音。 |
| `ui_observe` | 读取当前屏幕：前台应用、页面类型、焦点及其上下左右、按行编号的可选项；节点太少时附截图。 | 需要知道屏幕上有什么、选哪一个时用。按键、选择的结果里已经带回屏幕变化，做完一步不必再例行读一次。 |
| `ui_tap` | 把焦点移到屏幕上指定的一项，可选再按确认。返回最终焦点；没走到时说明停在哪、为什么。 | 「选第二个」「点进去」「打开那个狂飙」用它，目标用 `ui_observe` 的编号或文字。 |

### 6.7 其余工具和移除项

- `app_open`：并入 `app_search` 的按名搜索；别名补上优酷、芒果。
- `weather`：查某地某天的天气，默认用记住的所在城市；所在城市问一次后记进记忆。
- `web_search`（托管）：保留。语音回答不念来源和网址。
- `memory_read` / `memory_write`：保留，修正读写顺序的矛盾说法。
- **从电视目录移除**：
  - `ui_scroll`、`ui_wait`（翻页用 `ui_key`，等待放进各工具内部）。`ui_observe`、`ui_key`、`ui_focus`、`ui_tap`、`ui_input` 保留原名，电视上换实现（10-07 用户指出：同一能力用同一个名字）；
  - `app_search`；
  - `clipboard_*`、`conversation_read`、`setting_read`、`device_read`（「连的什么 Wi-Fi」这类需求另议）；
  - Skill 索引。

### 6.8 一轮结束与结果格式

- `app_open`、`media_control`、`volume_set` 都加进 `finishingTools`：成功就念模型带的那句话，不再请求第二轮；没确认或不符合预期时交回模型。
- 统一用 `status / retry` 新格式，改掉 `AgentLoop` 里的旧格式（P11）。给模型的是人能读懂的摘要，不是位掩码、代际号这类原始字段。
- 「做没做成」只能由回读决定，以 `video_search` 的假成功为戒。

### 6.9 评测要覆盖的易混说法

- 「暂停」 / 「返回」 / 「后退 30 秒」 / 「往回退一点」；
- 「下一个」：在播放页是下一集，在列表页是移动焦点；
- 「往下翻」 / 「选第二个」 / 「点进去」；
- 「静音」：包括已经静音时再说一遍；「取消静音」；静音时说「大点声」；
- 「快进」，在会弹会员提示的片子上。

比较两种设计：按键枚举里含媒体键、音量键，和不含。看选对率，以及有没有反向结果（静音被取消、暂停变继续、点进付费页）。

## 7. 提示词怎么改

### 7.1 结构

电视版不再用手机的基础段（`AgentPromptBuilder.kt:67-125`）加 `TvPromptProfile` 补丁，改成一份电视基础提示词，再加随工具注入的分节。目标是把固定开销从约 7.0k 压到 3k 以内。

| 段 | 内容（要点，不是最终措辞） |
|---|---|
| 场景 | 你是 Movo，在客厅电视上，用户多半离屏幕两三米、用语音和你说话，你说的话会被念出来 |
| 先判断 | 屋里的人声和节目台词也会被听到。这句话明显不是对你说的（台词、广告、家里人互相说话），就调用 `wait_for_user`，不要回答 |
| 做事顺序 | 播放控制、音量、开应用、天气这类有专门工具的，一次调用办完，不看屏幕；其他在屏幕上的事（找片、选择、翻页、关弹窗），读屏幕、按遥控器，像人一样看焦点、按键 |
| 歧义 | 先做最可能的那个，在回答里用半句话带出理解到的参数，方便用户顺口纠正（「好，放 2023 版电视剧《三体》」）；只有付费、开会员这类做错了难挽回的才先问。语音里反问一次的代价很高，排第一的候选多数时候就是对的（§3.5） |
| 说话 | 只保留一处长度规则（和语音段合并）；说结果不说过程；不念来源、网址；没做成就说看到了什么、用户可以怎么说 |
| 慢的时候 | 预计要几秒以上的工具（找片播放、界面操作），调用前先说半句「好，我找一下」。Movo 已有「执行卡工具前说明」，电视语音把它念出来即可 |
| 被纠正时 | 先照做，再一句话致歉，不辩解（C10 里先查记录再辩解 121 字） |

删掉：

- 手机数据源、发消息、Root、截图 schema 说明；
- redacted 占位（历史已经不脱敏）；
- 自绘键盘逐字输入（改由 `ui_input` 负责）。

### 7.2 每轮附上「电视现在的状态」

和时间一样，放在输入末尾的环境信息里，不影响提示缓存（见 `prompt-cache-env-plan`）：

```text
电视现在：前台 银河奇异果，正在播《狂飙》第 12 集 23:10 / 45:00（播放中）；音量 30；遥控能力可用。
```

有了它：

- 「暂停」「下一集」「还剩多久」「这是谁演的」都能直接一轮完成；
- 前台不是播放器时，也能看出媒体会话属于别的 App。

### 7.3 「不是对我说的」

真机上环境声和台词误触发是影响最大的失败（C1）。分两步做：

1. 先在提示词里给出口，加上 `wait_for_user` 工具（让模型调一个工具，比让它「输出空回答」更容易做到；OpenAI 的语音指南也是这么做的），用评测集衡量误触发和漏答。
2. 不够的话再在语音前端加一层判断。可选做法：
   - 节目在全屏播放时不开连续对话（华为的做法）；
   - 单独做一层「是不是对设备说话」的分类。

这不是隐藏的拦截策略：用户明确对 Movo 说的话照常回答，模型只是多了一个「不出声」的选项。

### 7.4 推理强度

电视语音的大部分请求是直达类，不需要长推理。建议语音轮把推理调到最低，用评测比较正确率和时延再定（C7 里一轮 820–1484 个推理 token、6–11 秒）。

## 8. 时延目标

以人按遥控器为基线（按记忆里的约定，慢要和人手对比，不替慢开脱）：

| 类别 | 人按遥控器 | 现在 | 目标 | 主要靠什么 |
|---|---|---|---|---|
| 暂停 / 继续 / 下一集 | <1–2 秒 | 9–17 秒（脚本，带核实） | ≤2.5 秒 | 状态直接给模型、一轮结束、关推理 |
| 音量 | 3–8 秒 | 7–8 秒 | ≤2.5 秒 | 相对调节、静音、一轮结束 |
| 打开应用 | 3–6 秒 | 2.8–9.5 秒（修复后） | ≤4 秒 | 已基本达到 |
| 找片到开播 | 15–40 秒 | 108–212 秒，或失败 | 不超过人手（≤20 秒，不含广告），再争取 ≤10 秒 | 通用遥控工具的闭环（走到目标、输入文字都在工具内完成），必要时包成 `video_play` |
| 问答开始说 | — | 5–72 秒 | ≤4 秒 | 天气工具、所在城市、不念来源 |

「说完 → 提交」那一段（断句）已经从 1.5 秒改成 0.65 秒，待实测；它不在本方案范围内。
