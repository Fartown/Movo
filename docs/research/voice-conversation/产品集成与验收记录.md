# 连续语音对话产品集成与验收记录

更新：2026-09-22。实现基线为 main `75152a7`，开发分支 `fix/voice-conversation`。本文记录产品代码和实测结果，不将此前独立 SDK 探针结果计为产品通过。

## 当前接法

采用已验证的 Dialog 客户端委托播报模式。`DoubaoDialogEngine` 使用官方 SDK 0.0.15.0 持有录音、AEC 与播放器；`VoiceConversationController` 管理会话，`VoiceTurnCoordinator` 管理用户输入、任务与播报的归属。现有 `EtaAssistantOverlayService` 增加 microphone 前台服务类型，页面显示和隐藏不销毁对话。进入对话前暂停 Sherpa 本地唤醒，SDK 真正销毁后恢复唤醒，禁止两个录音器抢麦。

`ASR_INFO` 选择客户端播报，`ASR_RESPONSE` 更新字幕，`ASR_ENDED` 后留 650 ms 补话窗口，再自动提交一次。窗口内再起声则合并未提交输入。R9 真机发现 PCM 已恢复、云 ASR_INFO 尚未到达时仍可能误提交；R10 增加本地 PCM 活动否决，等待下一 ASR 段合并。活动未获识别确认超过 6 s 则保留草稿并结束连接，禁止强行发半句话。无需手动结束录音或点击发送。当前输入端点参数为 custom VAD、1000 ms end smooth window，准确性以真实语料验证为准。

语音通过 `AgentAppState.sendVoiceMessage` 进入文字聊天同一 write-ahead、角色准备、模型配置、Runtime、历史与结果确认流程。保留当前 DeepSeek、推理强度和工具设置。语音风格作为公共 PromptBuilder 中的一条会话级系统消息，普通与角色会话均生效，不修改全局配置或历史正文。Runtime 增加语音参与时的原子准入、runId 持久化去重，以及 rejected/unconfirmed 的来源区分；断连不自动重发可能已执行的任务。

按用户明确要求，只播报本会话仍有输出权限的 LLM 最终正文，不播报思考、工具、执行日志或系统状态。失败和取消只显示在界面；R10 删除原有错误/取消状态的播报旁路。Dialog 的 `chat_tts_text`、question_id、reply_id 用于归属；默认豆包回答不进入 Movo 历史或播放器。每轮客户端选择并不关闭云端默认生成，费用不能按“只用了 ASR/TTS”估算。

播放器在收到匹配回复的合成结束、完整时长已流逝且实时输出静音尾段满足条件后结束播报；独立 TTS 的 3020 完成事件在 Dialog 探针中未出现，不能依赖该事件。新 ASR 轮由 SDK 自己中断旧播放，控制器在有效转写后撤销旧声音归属，任务继续；只有明确取消命令才请求取消 run。R15 仍观测到 ASR_INFO 后约 400 ms 原生播放尾部，未达原方案 300 ms 停声目标。“结束对话”关闭声音通道，已接受的任务继续保存文字结果，未提交的输入转草稿。

## 实施与原方案的关系

原方案中的自建共享采集、独立 ASR/TTS 会话及句槽设计是选择 Dialog 前的基线。Dialog 接法复用 SDK 录放和服务端轮次，没有再建设第二套自动降级链路。任务与声音分离、去重、未知状态对账、共享历史等产品契约保持。

以下门槛不能因换 SDK 而删除：唤醒连说是否丢字、中文句中停顿、真实外放可懂度、双讲保真、精确停声、后台和焦点中断、播放事实持久化。本文分别记录，不能将“设置了 AEC”当双讲通过，不能将合成 PCM 当用户实际听见。
