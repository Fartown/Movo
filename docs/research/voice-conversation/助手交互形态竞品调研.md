# 语音/文字助手交互形态竞品调研

> 调研对象：小爱同学（小米 HyperOS）、Apple Intelligence / Siri、Bixby（三星）、小布助手（OPPO ColorOS），并补充 ChatGPT 高级语音与 Gemini Live 作为"纯 AI 助手"对照组。
>
> **取证边界**：本文只写有公开出处的事实，每条给链接。没有找到公开出处的内容集中放在第 4 节"未证实项"，不写进事实表，也不作为 Movo 设计的论据。厂商一手页面（Apple 支持文档、小米开放平台、ColorOS 官网）优先；二手媒体来源在表中单独标注。

## 1. 调研问题

设计 Movo 的助手交互前必须回答五个问题，它们对应用户反馈的"对话、浮窗、语音交互乱七八糟"：

1. 助手从哪些入口进入，进入后是**全屏页**还是**局部浮层**？
2. 语音和文字是**两个界面**还是**同一界面的两种输入**？
3. 从语音切到文字（以及反向）时，**会话上下文、未发送的内容、正在执行的任务**怎么处理？
4. **播报**是固定行为还是可配置策略？字幕怎么显示？
5. 连续对话、打断（barge-in）、判断说完是不是基线能力？

## 2. 事实表

### 2.1 Apple Intelligence / Siri

| 事实 | 出处 |
|---|---|
| "Type to Siri" 是设置开关，位置为 设置 → Apple Intelligence & Siri → **Talk & Type to Siri** → 打开 **Type to Siri** | [MacRumors](https://www.macrumors.com/how-to/ios-type-to-siri/) |
| 唤起文字输入的手势是**双击屏幕底部边缘**，唤出的输入界面带推荐问法，输入后点向上箭头提交 | [MacRumors](https://www.macrumors.com/how-to/ios-type-to-siri/) |
| 可以**点击 Siri 界面内的麦克风图标切回语音**，即语音与文字在同一个 Siri 界面内互切 | [Tom's Guide](https://www.tomsguide.com/ai/apple-intelligence/how-to-use-apple-intelligences-type-to-siri-feature-on-your-iphone)、[pocket-lint](https://www.pocket-lint.com/how-to-use-type-to-siri-on-ios/) |
| 文字提问时 Siri 的响应方式与语音提问一致，并**在多条消息之间保持上下文**，支持自然来回对话 | [MacRumors](https://www.macrumors.com/how-to/ios-type-to-siri/) |
| 播报是三档可配置策略：**Siri Responses** 下可选 **Prefer Spoken Responses / Prefer Silent Responses / Automatic** | [Apple 支持](https://support.apple.com/guide/iphone/change-siri-settings-iphc28624b81abc/ios) |
| 字幕独立于播报：**Always Show Siri Captions** 常显 Siri 的回答文本，**Always Show Speech** 常显用户自己被识别出来的请求文本 | [Apple 支持](https://support.apple.com/guide/iphone/change-siri-settings-iphc28624b81abc/ios) |

**要点**：Siri 把"说/打字"做成**同一界面的输入模态切换**，把"要不要出声"做成**独立于模态的设置策略**，把"字幕"做成**独立于播报的第三个开关**。三件事正交。

### 2.2 小爱同学（小米）

| 事实 | 出处 |
|---|---|
| 小爱同学 3.0 在手机上实现自然连续语音对话：**一次唤醒后连续对话、随时打断** | [小米小爱开放平台](https://developers.xiaoai.mi.com/xiaoai3) |
| 唤醒动画**与系统界面融合**，支持文字、语音、图片、文档、屏幕等多种内容的识别与问答 | [小米小爱开放平台](https://developers.xiaoai.mi.com/xiaoai3) |
| 超级小爱的界面与系统界面合并，可**在任意页面唤起并交互，没有独立 App 的体验**（二手来源） | [AIHub 词条](https://www.aihub.cn/tools/chatbot/hyperai/)、[知乎体验文](https://zhuanlan.zhihu.com/p/19720694474) |
| HyperOS 新版支持全双工连续对话，可随时打断并继续（二手来源） | [中关村在线](https://ai.zol.com.cn/910/9100143.html) |
| 长对话可在"小米音箱"App 内以文本形式回看对话内容（二手来源） | [知乎](https://zhuanlan.zhihu.com/p/1907217806430302279) |

**要点**：助手是**系统层的一层浮层**，不是一个会抢占前台的 App 页；连续对话与打断是基线；语音发生的内容能以文本形式回看。

### 2.3 Bixby（三星）

| 事实 | 出处 |
|---|---|
| Bixby 的语音输入以**系统键盘的听写**形态存在：只要键盘可见，在任何 App 内长按 Bixby 键即可开始听写 | [Samsung 支持](https://www.samsung.com/us/support/answer/ANS00076751) |
| 启用非三星键盘时 **Bixby voice input 不可用**；需 Android 13 / One UI 5 以上并启用三星键盘（二手来源） | [The Tech Outlook](https://www.thetechoutlook.com/new-release/software-apps/tips-to-use-bixby-voice-input-by-enabling-samsung-keyboard-issued-by-samsung/) |
| One UI 8.5 的新 Bixby 更准确理解日常语言，并可直接操作 Galaxy 设置（二手来源） | [Gadget Hacks](https://samsung.gadgethacks.com/news/samsung-bixby-upgrade-revealed-in-one-ui-85-update/)、[Yahoo Tech](https://tech.yahoo.com/phones/articles/bixby-change-phone-settings-just-120000619.html) |

**要点**：三星把"语音听写"和"语音助手对话"拆成两件事——听写挂在键盘上、服务于任意输入框；助手对话是另一条链路。这与 Movo 已有的"语音听写 / 语音对话"两模式划分一致。

## 3. 共性机制归纳

把上述事实去掉厂商差异，剩下五条是所有家都成立的：

| 编号 | 机制 | 支撑事实 |
|---|---|---|
| C1 | **一个会话，两种输入**。语音和文字写同一条对话历史，切换不新建会话、不丢上下文 | Siri 文字提问保持上下文；Gemini Live 同会话内打字后继续语音；ChatGPT 转写落回同一会话 |
| C2 | **模态是界面内的开关，不是另一个页面**。切换动作是"点麦克风 / 点键盘"，不是"退出再进另一个入口" | Siri 界面内点麦克风切回语音；小布同一助手里键盘/语音/文档/圈选并列 |
| C3 | **播报是可配置策略，且与字幕正交**。是否出声、是否显示回答文本、是否显示用户话的识别结果，是三个独立开关 | Siri 的 Siri Responses 三档 + Always Show Siri Captions + Always Show Speech |
| C4 | **连续对话与随时打断是基线**，不是加分项 | 小爱 3.0 一次唤醒连续对话随时打断；Gemini Live 可打断 |
| C5 | **助手是系统上的一层浮层，不抢占前台**；语音发生的内容必须能以文本回看 | 超级小爱与系统界面融合、无独立 App 体验；小米音箱 App 回看文本；Gemini Live 转写进历史 |

## 4. 未证实项（不作为设计论据）

以下内容在本轮公开检索中**没有拿到可引用的一手出处**，因此不写入事实表，也不用来论证 Movo 的设计：

- 小爱同学、小布助手唤醒后浮层内"切键盘输入"的**确切控件位置与手势**。检索只证实了它们同时支持语音与键盘输入，没有证实面板内的切换控件形态。
- 各家判断"用户说完"的**静音阈值数值**与端点算法。
- Bixby 是否支持"语音助手会话内语音↔文字互切并保持同一上下文"。搜索只证实了键盘听写这条链路。
- 各家在 Agent 执行长任务期间的**最小化形态**（胶囊/灵动岛/状态栏）的具体规则。
- HyperOS"全双工"的技术含义（是否为真全双工声学链路），二手来源用词不足以判定。

需要这几项作为依据时，应在真机上实测对应系统并留证，而不是引用媒体描述。

## 5. 对 Movo 的直接结论

| 共性机制 | Movo 现状 | 差距 |
|---|---|---|
| C1 一个会话两种输入 | **不成立**。浮层内打字走临时会话 `eta_assistant_<uuid>`，语音走 App 选中的会话，两者历史不同（见 `docs/solutions/assistant-interaction.md` 第 2 节证据） | 必须先统一会话，这是"乱"的根 |
| C2 模态是界面内开关 | **不成立**。App 聊天页点麦克风会另弹一个全屏悬浮窗；语音态下文字发送被直接 `return` 掉 | 必须把语音做成当前面上的模态位 |
| C3 播报与字幕正交可配置 | **不成立**。播报行为写死为"语音态播最终正文"，没有设置项；字幕与输入框草稿共用一个变量 | 需要拆变量 + 加设置 |
| C4 连续对话与打断 | **已成立**。连续多轮、自动提交、插话替换已有真机记录（见[产品集成与验收记录](产品集成与验收记录.md)） | 保持，不回退 |
| C5 浮层不抢前台 + 文本可回看 | **部分成立**。浮层不抢前台成立；但 GUI 工具执行时浮层是直接隐藏，用户看不到助手还在不在；浮层内的文字轮次不进 App 会话历史 | 需要最小化胶囊态 + 统一归档 |

设计方案见 [`docs/solutions/assistant-interaction.md`](../../solutions/assistant-interaction.md)。
