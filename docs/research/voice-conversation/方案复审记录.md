# 连续语音方案复审记录

评审日期：2026-09-22。范围：[主方案](../../solutions/voice-conversation.md)、[状态与协议](../../solutions/voice-conversation-state-and-contracts.md)、[火山选型](火山语音能力与复用选型.md)，并对照当前代码 `9b5b58dc476033511711cee2eaebe7c8c8c0458d`、官方 SDK 文档和示例源码。

**结论：原稿存在会误取消任务、重复执行、音频串轮和大幅增加开发量的问题，不宜照原稿直接开工。已修正文档并收敛首期范围；SDK、声学与实际延迟仍需 P0 验证，当前不能宣称方案已获运行验证。**

“已修正”在本文仅指设计文档，产品代码尚未修改。P1 为影响正确性或架构落地的问题，P2 为交互与维护问题；实施工作包 P0 是能力验证阶段，与问题优先级不是同一个编号体系。

后续验证：2026-09-22 已执行 [P0 能力实验](P0能力验证.md)。独立 SDK 和 DeepSeek 组合有真实设备出声证据；ASR 分句与用户轮次不同、合成完成与播放完成不同均得到实测支持。AEC 双讲、精确停声/恢复、完整端点和整轮首声仍未通过，不能将本次组件验证当作产品交付验收。

## 1. 发现与修订

### R01 · P1 · Runtime准入缺失，新入口会取消原任务

**触发例**：用户在语音任务执行中打开聊天发送另一句；原稿只限制“一个语音会话一个run”，未约束Runtime的其他入口。现有服务 `ingestRunRequest` 会替换pending，`startRun` 会调用 `activeSession?.controller?.cancel()`；新语音架构并不能自动改变这个行为。

证据：[AgentRuntimeService.kt](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRuntimeService.kt)，L270–289、L338–347；内部结果卡续跑也能直接调用startRun。

**修正**：涉及语音时在服务端对pending和active原子准入；相同runId去重，其他任务BUSY不暗替换。显式替换先取消、确认终态、归档，再提交新任务。所有内部启动路径共用准入，不能只锁UI按钮。落点：主稿§5.7；附录§6.2；V21。

### R02 · P1 · 客户端“失败”不代表任务确定失败

**触发例**：任务已经开始，Binder断连，Client生成 `ok=false`。若据此开始下一run或“重试”，旧操作可能已成功，造成重复执行。中断等待时发出cancel也不等于取消已经完成。

证据：[AgentRuntimeClient.kt](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRuntimeClient.kt)，L62–104；[RunResult](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRuntimeWire.kt)，L206–218，当前无终态来源或取消类型。

**修正**：分离可信服务端终态、服务端未执行拒绝和本地TransportUnknown。未知时保留原runId，通过pending/active、attach、checkpoint、outbox对账；查无active本身不证明从未执行。`ok/error`继续兼容旧显示，不能按中文错误字符串识别取消。落点：附录§6；V16–V18。

### R03 · P1 · 把普通插话默认解释为取消任务

**触发例**：“嗯”“要多久”“再补充一下”会让旧任务被取消；若发生在发送或写操作之后，用户还可能误以为动作被撤回。原附录同时提出自动pause检查点，但现有controller只有一个pause布尔值，恢复语音暂停可能解除用户主动暂停。

证据：复审前主稿§5.7/附录§5.2；[AgentRunController.kt](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRunController.kt)，pause/resume/steer是不同机制，steer仅排队下一模型轮，并不打断当前工具批次。

**修正**：先让声，再处理明确意图；普通插话不取消，明确停止/替换才cancel。首期不新增语音自动任务pause/steer协议，保留一个待处理输入槽；模糊纠正澄清，已执行事实保留。结束声音对话与停止任务拆开。落点：主稿§2.2/5.7；附录§5；V10–V15、V20。

### R04 · P1 · 主稿与附录仍写HTTP，和SDK选型冲突

**触发例**：按正文开发会同时建设HTTP合成器、AudioTrack、帧游标和SDK适配器；不同段落给出了不同的默认路线。顶部“以后按PoC收敛”没有解决实施歧义。

证据：复审前主稿§3.4/系统图/目录/模块表、附录§4.2均明确采用HTTP；火山选型却优先官方独立TTS SDK。

**修正**：全文统一现有ASR + Movo/DeepSeek + 独立TTS SDK。HTTP播放器移出首期；RTC只留后续可选研究，不把两条路线都变成必做任务。落点：主稿§0/3.3/4.2/5.2/6.1；附录§4；火山调研§4–5。

### R05 · P1 · 把SDK暂停、合成结束和精确播放进度混为一谈

**触发例**：CancelSession后本地缓存仍播放；SessionFinished到达就开始续听空闲倒计时；旧句迟到finish回调被归到新句。原稿使用自有AudioTrack游标，却没有证明SDK内置播放器暴露同等能力。

证据：[官方独立TTS SDK](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-tts-android-sdk-interface-documentation?lang=zh)区分暂停/恢复、合成会话与播放回调，并明确同步stop不能在回调线程执行。已下载官方demo中的 `BiTtsActivity` 也分别处理这些事件；未运行demo。

**修正**：独立adapter、一个有界句槽、engineGeneration隔离、专用线程停播屏障。合成结束和播放结束同时满足才推进；句级记录，不虚构精确字/帧进度。SDK暂停/恢复是否无重复、停止后是否残留声音仍是P0硬门槛。落点：附录§4；V10–V11、V22–V24。

### R06 · P1 · 为提前播报改造整个模型与历史系统，范围过大

**触发例**：原稿要求各provider保证不可撤回正文、增加speech事件、处理replay、修改opaque引用和所有压缩入口。既复杂，又可能破坏工具调用配对或使未播回答一直不能压缩。

证据：复审前主稿§5.2/5.6，附录§4.1/6.1/7.2；现有 [AgentContextSession](../../../app/src/main/kotlin/io/github/mangi/eta/agent/model/AgentContextSession.kt)已经明确分开durableHistory、transcript与system消息。

**修正**：首期只播正常run最终稳定正文，不新增全provider speech协议；保留原始事实和opaque历史。播放状态单独存，下一run在公共PromptBuilder增加有界交付说明。roleplay、systemCount计算和系统消息刷新必须共用该参数，不能仅拼config.systemPrompt而在角色模式失效。落点：主稿§5.6；附录§4.1/7.2；V32。

**取舍**：这会增加首声等待；交付说明改善上下文但不提供严格“用户已经听见”的证明。不是没有代价的减负。

### R07 · P1 · 空闲超时与任务耗时未分离

**触发例**：用户提出耗时20秒的任务，15秒续听计时器触发结束甚至取消；助手还在说话时把无输入误当空闲。原稿给了多个时间值，但没有完整定义计时器适用状态。

**修正**：仅无输入、无执行/未知状态、无待播/暂停输出、无pending输入时才启动空闲计时。起声、收尾、ASR尾结果、VAD屏障、取消待确认、任务等待各自独立；长工具不自动空闲退出。落点：主稿§5.5；附录§3.3；V19。

### R08 · P1 · 分句信号不能直接替代用户轮次

**触发例**：用户说“先查一下……再发给我”，800ms静音分句被当作整轮，提前执行前半句；每次full全文被追加造成重复。尾包之后补话和VAD线程延迟又会造成丢话或分错turn。

证据：当前 [DoubaoSaucProtocol](../../../app/src/main/kotlin/io/github/mangi/eta/agent/voice/asr/DoubaoSaucProtocol.kt)配置 `end_window_size=800`；[识别引擎](../../../app/src/main/kotlin/io/github/mangi/eta/agent/voice/asr/DoubaoBidirectionalAsrEngine.kt)在 `frame.isLast` 才收尾。[官方ASR](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)区分稳定识别分句与流末尾。

**修正**：保留本地VAD和有界端点；full替换、definite只作稳定证据；按采样边界处理补话，提交前水位屏障有500ms上限，每段尾结果5秒、每turn最多8段/90秒，失败不执行半句。短控制词另测，不以普通起声阈值过滤。落点：附录§3；V04–V06。

### R09 · P1 · AEC和后台音频仍是能力缺口

**触发例**：助手把自己的外放当新指令；工具隐藏浮窗后失去焦点；切蓝牙后既不能打断也不能播。独立ASR+TTS不能自动继承端到端Dialog SDK内置AEC。

证据：本项目minSdk=34、targetSdk=36；[Android AEC](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler)的isAvailable仅报告设备是否实现该效果；[音频焦点规则](https://developer.android.com/media/optimize/audio-focus)对目标Android15及以上的顶部应用/前台服务有要求。

**修正**：P0先验证原麦FGS承载会话、原生AEC与外放双讲、SDK播放停止、路由切换、Android目标版本和原生库兼容。软件AEC需能对齐实际播放参考，不能把它写成随手接库即可解决。落点：主稿§5.4/6.1；V25–V27。**仍待设备验证，不能仅通过文档修订关闭。**

### R10 · P1 · 最终正文路径与原首声目标不自洽

**触发例**：DeepSeek开启思考、完整答案生成较慢，即使TTS首包很快，仍无法实现“用户停下后两三秒开口”。“处理中”提示不能算作答案首声。

**修正**：显式拆分端点、ASR尾延迟、准入、模型完整生成、TTS和设备播放。保留P50≤2.5s/P95≤4s作为无工具短问答目标，标未达标；按实际模型和推理配置分组。最终正文路线不达标时，带证据评审稳定流式正文等优化，不能偷偷换模型或关思考。落点：主稿§0/6.2；V31。**仍待测量。**

### R11 · P1 · 持久化、ACK、上下文与恢复边界不完整

**触发例**：把终态ACK拖到播报完成，会让未听完的结果反复交付；进程重启把历史事件再播一遍；每轮默认modelSessionId=runId导致失去连续上下文；另造voice handoff source又使原会话/角色链路不识别。

证据：[AgentRuntimeWire](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRuntimeWire.kt)的effectiveModelSessionId回退逻辑；[AgentRuntimeRunExecutor](../../../app/src/main/kotlin/io/github/mangi/eta/agent/runtime/AgentRuntimeRunExecutor.kt)通过AGENT_UI_HANDOFF解析conversationId与角色上下文；现有大结果采用contextSnapshotRef。

**修正**：固定同一conversationId/modelSessionId，保留既有handoff并添加voice元数据；完整解引用后幂等归档/ACK，播放进度独立更新。来源先登记、恢复只显示文字和执行状态，旧音不自动重播。跨进程依赖outbox+幂等归并，不假定一个全局事务。落点：附录§1/6.3/7；V16–V18、V28–V32。

### R12 · P2 · 暂停/静音、配置热变更和错误重试语义混杂

**触发例**：用户只想关麦却停了任务；对话中换模型/密钥，前后半句走不同配置；TTS失败后的重试误把Agent重跑。原稿没有说清结束声音会话后的待处理输入是否仍会执行。

**修正**：拆麦静音、停止朗读、结束对话、停止任务。麦静音停止物理采集，活跃对话不派发KWS唤醒事件；模型/音色固定会话版本，下次生效，撤销能力立即停对应资源。试听互斥，各层分别重试。结束对话后pending变草稿不自动执行；页面/本地等待中断只detach，不沿用旧run()自动cancel行为；系统暂停后不突然外放。落点：主稿§5.4/5.8；附录§5/6.1/7.3；V20、V26–V30。

## 2. 复审后的开发边界

保留：连续对话全闭环、共享麦、自动端点、免触屏多轮、自然插话、明确取消、真实声音与恢复。

首期删除的工作：自建HTTP/AudioTrack播放链路、全provider提前speech事件、裁剪opaque历史、为所有未播内容修改压缩策略、语音自动pause/steer控制协议、必做RTC控制面PoC。

必须补上的工作：Runtime服务端准入、传输未知与可信终态分离、有界待处理输入、计时器门控、SDK停播与回调隔离、公共语音上下文参数、幂等持久化/ACK。

不是简单地“把所有代码再做一遍”，也不能仅加一个TTS调用就交付。开发量已收敛，但没有实测依据承诺减少百分比或人日。
