## 已实现

### 显示刷新随可见生命周期停止

`Lifecycle.pollWhileStarted()` 在 STARTED 时立即刷新、STOP 时取消，恢复后重新刷新。诊断页和运行卡住提示接入该逻辑。卡住提示原有“流式且未暂停”的调用条件保留，这一处解决执行期间的后台显示工作，不被当作无任务轮询问题。

浏览器预览也只在 STARTED 期间按原有 1.2 / 4 秒节拍刷新；显示期间持有浏览器使用权，STOP 或组合销毁时释放。

### 共享浏览器按使用权挂起

新增 `BrowserIdleController`，由主线程维护使用计数。每次获取返回独立、可幂等关闭的 `AutoCloseable`；其他线程关闭会投递回主线程。最后一个使用者离开后只安排一次 5 秒延迟，新使用者出现取消延迟。已暂停时，新使用者会在取得使用权前恢复页面。没有新增周期检查、前台服务或 CPU 唤醒锁。

以下路径持有使用权：

- 整轮 Runtime run，覆盖模型思考与工具调用间隔，并在执行线程 finally 释放；新旧 run 重叠时互不误释放。
- 浏览器页面和预览卡在 STARTED 期间；会话的用户接管归属与页面是否可见分别管理。
- 单次浏览器操作，覆盖直接调用和没有 Runtime run 的用户操作。
- 主页面导航，包括网页内点击；重定向保留同一份使用权，匹配 URL 完成、失败、停止、销毁或原有工具导航超时后释放。

真正闲置时调用共享 WebView 的 `onPause()` / `pauseTimers()`，恢复时调用 `resumeTimers()` / `onResume()`。本次全仓源码只发现这一处 WebView 实例，登录走外部浏览器；由于 timers 是进程级状态，以后新增 WebView 必须一起纳入使用权管理。

暂停不清 Cookie、历史或页面数据，不调用 reset / destroy。销毁原实例时恢复全局 timers，避免影响后续实例。同步主线程调用在等待取消/超时后，未执行的请求跳过；迟到取得的使用权会立即释放，避免泄漏。

## 行为与边界

- 5 秒是防止短时切换反复暂停的初始值，没有被表述为实测最优值。
- 用户发起但仍未完成的导航保持运行，未新增强制截止时间。若网页永远不结束加载，该使用权也会保留到停止、失败或销毁；异常网页导航的有界保活策略留待单独验证，不能靠“无输出”判断其完成。
- 不可见且没有上述使用者的网页，其 JavaScript 定时器会暂停；这会改变原先隐藏页面仍继续运行的行为。当前没有独立的后台网页媒体或下载保活产品流程，本次也没有新增它们。
- `pauseTimers()` 不保证终止所有网络请求或音频。真实 WebView、媒体、重定向及后台恢复仍需目标设备验证。
- 终端、Linux daemon、语音唤醒范围、执行服务租约和常驻球设置不作改变。进程驻留、执行 FGS 和 CPU 唤醒锁没有混为同一件事。
