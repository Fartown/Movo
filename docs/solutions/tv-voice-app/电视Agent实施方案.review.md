# 电视 Agent 实施方案 评审报告

- 评审时间：2026-10-07
- 评审对象：`docs/solutions/tv-voice-app/电视Agent实施方案.md`
- 评审方式：三路独立评审（A：Claude subagent；B：TRAE CLI；C：Codex CLI），三路都成功完成
- 评审重点（用户要求）：工具设计的合理性、准确性，包括入参出参、实现、手机和电视的区分、架构
- 总结论：**需重大修改**（三路一致）
  - 三路都认可大方向：工具按「管什么」拆分；同名工具按设备分开装配；导航闭环放在工具内部；`volume_set` 用显式静音。
  - 问题集中在三处：
    - 工具实现和真机证据对不上；
    - 契约没有闭合，包括观察编号、部分结果、参数组合、静默结束；
    - 安全和迁移，包括付费保护、前置修复、回滚。

## Premortem 汇总

1. **B站播放控制大量失败或反向（三路一致）**：会话的判断不对，按键序列和实测不一致，确认键是切换键，媒体键可能投给后台 App。已升级为 #4、#5、#7、#8。
2. **腾讯找片在真机上超时或选错（三路一致）**：截图路线的目标对应、模型能力、逐字耗时、交错干扰都没解决，首字母搜索的命中率也没验证。已升级为 #13、#15、#16、#19。
3. **小样本验收侥幸通过，上线后才暴露问题；同时手机回归、旧路径已删、没法止损（三路一致）**：已升级为 #17、#18、#19、#20、#22。
4. **在会员或付费页上按了确认（B，A、C 部分提及）**：已升级为 #1。

## P2 建议项

- **页面判断会误判**：B站首页预览、腾讯详情页小窗都会被判成「播放」。判断「播放」要加全屏条件，判断不了就不给（A，C 部分）。
- **`paid` 关键词会大量误报**：内容卡片上的「VIP / 会员」角标会被当成付费入口。只给短按钮标付费，角标另标（A）。
- **同名工具的参数名两端不一致**：手机用 `index`，电视用 `id`；电视 `ui_input` 收到中文怎么处理没定义（A）。
- **没有复用分析**：现有 `UiObservationRegistry`、`TvMediaControl` 的回调确认、`RealVolumeSetBackend` 为什么不复用，没有说明（A+B+C）。
- **基线数字混用**：38% 来自奇异果脚本，不是 B站、腾讯（C）。
- **固定开销 ≤3.5k 没有拆预算**（A）。
- **找片时没说 App 的情况**：选 App 的规则（调研 D4）没写进方案（A）。
- **设置页和胶囊**：设置页要显示「遥控 / 截图 / 看图」三项能力状态；静默轮时胶囊怎么收起没写（A）。
- **用户中途接管**：用户拿起遥控器时，工具内部的按键循环要逐键检查取消（A）。
- **证据引用更正**：roundE 截图耗时；T4b 关于腾讯 seekTo 的说法（A）。
